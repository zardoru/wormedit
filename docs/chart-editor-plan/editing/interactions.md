# Plan slice: editing interactions and commands

[Back to the editing-plan index](../editing.md).

## Selection

When Compose is visible, the note-editing canvas has first priority for editing and navigation. Wheel, pan and insertion gestures must act on their first event without a prior focus click. Keyboard navigation and insertion target it when no text/IME editor or dialog owns input. Preserve pointer occlusion and matching release ownership; hidden Compose must not consume other tabs’ events (T-303).

Mouse area selection is a first-class editing gesture. Pressing on empty chart space and dragging creates a visible selection rectangle in chart coordinates; dragging works in all four directions and remains correct through zoom, vertical scroll, split-stage gutters, and the BGM pane's independent horizontal scroll. Notes, hold heads/tails/bodies, timing markers, BGM events, and BGA events are hit-tested through controller geometry rather than renderer pixels. The active pane supplies the default event/lane scope, with an explicit all-visible-tracks mode for cross-track work.

Every captured transform draws backend-neutral ghosts before it mutates the document. Moving notes or mixed selections shows the complete proposed objects at their snapped destinations while retaining a subdued origin silhouette; hold creation/resizing shows head, body, tail, and any union/removal result; range and recipe handles show their proposed bounds; and timing/BGM/BGA drags show their type-specific marker or clip geometry. Valid, destructive-normalizing, and invalid/conflicting previews use distinguishable treatments that do not rely on color alone. Ghosts are revision-bound, obey the same clipping/lane transforms as committed objects, disappear on commit/cancel/focus or capture loss, and are derived from the exact command proposal so the committed result cannot differ silently from the preview.

During the drag, show the prospective selection without mutating the committed selection. Edge proximity auto-scrolls the relevant vertical and horizontal view while the anchor remains fixed in chart coordinates. Pointer capture keeps the gesture valid outside the original pane. Mouse release commits one selection command; Escape or pointer-capture loss cancels and restores the prior selection. A drag that crosses the movement threshold must not also place a note when released.

Use consistent modifiers: an unmodified box replaces selection, Shift adds, the platform primary modifier toggles, and Alt subtracts. Direct clicking uses the same set algebra. Selection is limited to the active BMS branch projection; locked/hidden semantic layers and disabled tracks are excluded unless the user explicitly enables their selection. Results use deterministic document order so Shift + lane and other successive commands behave predictably.

Selection gestures operate through a headless `area_selection_controller_t` that consumes pointer positions, viewport transforms, modifier state, and hit-test records, then returns preview/commit/cancel actions. Rendering only draws its returned rectangle and highlights.

The initial headless controller implementation supports note heads, hold tails, and hold-body intersections in the playable note field, using revision-bound measure/span indexes and replace/add/toggle selection modes. Its current bounded slice covers one continuous lane field with vertical zoom and scroll; BGM events, timing markers, BGA events, split-stage gutters, independent horizontal scrolling, and edge auto-scroll remain outside this controller contract.

Mouse input is a complete note-authoring path. In the active placement tool, moving over an empty playable cell shows a snapped ghost note with its lane, row, note kind, armed sample, and collision validity; a click creates or toggles the note through the same command used by lane keys. Dragging may paint notes at newly crossed snapped cells as one transaction, with duplicate cells suppressed, while a movement that begins as area selection never also places a note. Hold placement uses either an explicit hold tool or **Alt/Option + press-drag** and is bidirectional around the pressed row. Dragging later/downward keeps the pressed row as the head and moves the tail; crossing earlier/upward keeps the pressed row as the tail, moves the head upward, and extends the duration by exactly that delta. Crossing back through the origin swaps the moving endpoint continuously instead of producing a reversed hold; returning exactly to the origin previews a tap.

StepMania-style overwrite normalization applies to direct lane entry and new hold drawing. Pressing a lane key on an occupied editable tap or hold at the cursor removes that object rather than adding a duplicate. A new hold removes editable taps covered on the same lane and unions with every touching or overlapping editable hold into one continuous hold; the full removal/merge set is previewed and committed atomically with the new interval. The initiating note supplies the resulting head's armed sound/presentation values, while conflicting layered sounds, semantic metadata, locked notes, mines, invisibles, rolls, or other target-specific kinds require an explicit policy or reject instead of being silently discarded. Undo restores every consumed object and its identities/provenance.

When playable notes are selected, the clicked selected note becomes the duration reference: its previewed duration determines one exact signed delta, and every selected note previews that same duration delta while retaining its start row and relative duration difference. Taps participate as zero-duration notes and become holds when the resulting duration is positive; a resulting zero duration becomes a tap, while a negative duration rejects the entire resize. Clicking outside the selection first follows the normal replace-selection rule and resizes only that note. Group resize is one atomic command, and any member with a negative duration, unavailable tail lane, or unresolved collision rejects the whole preview. Losing pointer capture, pressing Escape, or releasing the modifier cancels the gesture. Invalid or incompatible results do not mutate the chart, and an unmodified drag retains its normal selection or paint meaning.

All editable chart objects expose hover state through controller hit-test records rather than renderer-only state. Notes, hold parts, BPM and other timing markers, BGM/BGA events, measure boundaries, anchors, and slice handles show a clear hover outline/cursor and a concise value tooltip where useful. A single click selects or positions the cursor according to the active tool; a double click opens the type-specific inline editor or properties popover, so double-clicking a BPM marker edits its BPM and double-clicking a note edits its label, layer, kind, and sample fields. Double-click timing thresholds and pointer slop use platform settings where SDL exposes them, and the second click must hit the same stable object ID. Keyboard activation can open the same editor for accessibility and test parity.

Double-clicking an empty row of a visible timing-data lane creates a lane-typed provisional event at the exact snapped row, matching iBMSC's timing-object workflow. The provisional BPM, scroll/SV, speed, stop, delay, warp, kiai, meter, or anchor marker is rendered as a pseudo-note in that lane and immediately opens the same inline value editor used by an existing event. Its initial value comes from an explicit per-type default or the effective value at the cursor, visibly identified before commit; Enter or focus-confirm inserts one typed event, while Escape, invalid input, timing lock, an illegal same-row combination, or revision change cancels without mutation. This pseudo-note is presentation and transaction state, never a playable `note_t`. Creation uses the ordinary revision-checked timing command, exact snap policy, deterministic same-row ordering, collision rules, and one-step undo/redo.

BPM entry is decimal-first even though timing evaluation remains exact. The inline editor, property panel, marker label, and common keyboard entry accept and display familiar decimal BPM text such as `174`, `174.5`, or `174.375`; parsing converts the base-10 spelling directly to an exact rational without passing through binary floating point. Preserve the user's valid decimal spelling as provenance where practical. A configurable decimal stepper defaults to `0.01` BPM with coarse/fine modifiers. Fraction syntax and the exact numerator/denominator are available through an advanced disclosure for generated or analytical values, not imposed on ordinary editing. When an exact derived/imported rational has no bounded terminating decimal, show a clearly marked rounded decimal at the configured display precision while retaining the untouched exact value and exposing it in a tooltip/advanced field; merely opening or closing the editor must not quantize it. On actual decimal edit, preview the exact parsed value and any target-format rounding before commit. Reject empty, non-finite, nonpositive, overflowed, or over-cap precision values with an inline diagnostic rather than partially changing timing.

An area or Shift-navigation selection over the scroll/SV lane can be supplied to an **Add SV Function** command. The command creates a durable, non-destructively editable recipe with an exact musical interval, named deterministic function/easing and parameters, target family, fixed or adaptive export sampling policy, and optional integral normalization. Applying the dialog commits only that recipe—not its sampled control points—as one undoable command. The selected interval remains an editable range object: its start, end, and whole-span handles can be clicked and dragged, snapped through the active exact grid by default, with a live unsaved preview and cancel/commit semantics. Reversing endpoints normalizes their order; zero-length and out-of-chart ranges are diagnosed; timing lock, revision changes, or unrepresentable grid moves reject without partial mutation.

SV function recipes are composable. Every recipe evaluates to a multiplier, and overlapping recipes multiply pointwise with the base authored SV in deterministic stable recipe order; no recipe destructively replaces another recipe's output. The UI can reorder, enable/disable, duplicate, and edit each recipe independently, and shows the individual curve plus the multiplied effective result. Values, infinities, zero crossings, integral behavior, and target limitations are validated before export. Preview may generate a bounded transient sample cache for drawing and compatibility diagnostics, but native project save retains the functions, intervals, parameters, ordering, and policies—not a materialized event cloud. Only an interchange exporter samples the composed result into the minimum deterministic target events required by its selected accuracy/bounds profile; export remains read-only with respect to the project document.

`SPEEDS` markers must make their transition extent legible without turning the timing lane into a solid block. Hovering or focusing one marker draws a light translucent span over the rows or audio-time interval it affects, while the marker itself retains the stronger event color. Derive that span through the shared speed/timing evaluator—including beat-based versus seconds-based duration, stops, and warps—so the editor overlay matches preview and export behavior; overlapping hover spans compose visually but do not imply an edit.

Outside live chart playback, retain a lightweight line/curve overlay above the SV lane connecting the effective composed values so authors can read the intended note-field motion without enabling the full moving-field preview. The overlay is derived from the same evaluator and exact coordinates as export, is decimated only in screen space, remains distinguishable from selection, recipe range handles, and authored point markers, and never becomes editable source data itself.

Maintain an exact inclusive area range by holding Shift while navigating the cursor with the keyboard. Navigation moves the live tail; releasing Shift commits the range. Reversed endpoints normalize, and Escape, focus loss, revision/chart changes or an input-owning modal cancel the preview without editing the document. Shift plus mouse dragging retains its existing offset gesture. Space starts playback or invokes hard Stop, never Pause; focused text and IME retain input ownership. T remains the tap-timing key. This user decision (2026-10-01) supersedes the earlier Space-anchor/tail gestures; implement it in T-296.

### Quantization and row transforms

Quantization moves selected row data to the nearest point on a grid requested by the user. A `quantize_request_t` contains the stable event IDs or selected row/range, event-family scope, exact destination grid, tie policy, hold policy, collision policy, and anchor policy. The UI may take the grid from the active snap or accept a numeric division count directly.

Offer two clearly named grid bases because variable-length measures make them different:

- **standard-measure divisions** place points at exact multiples of `1 / d` of a standard 4/4 measure, matching the chart's global resolution and snap model;
- **per-measure divisions** divide each authored measure into `d` equal local cells, matching BMS-style row quantization even when `#xxx02` changes that measure's length.

Events at the same exact source position form a row and receive one computed destination, preserving chords and coincident keysound layers. Only objects in the requested scope move; a whole-row option deliberately includes every editable object on selected rows. Notes and BGM events are the normal scope. BPM, SV, stops, delays, warps, kiai, bookmarks, and other timing/navigation data require explicit inclusion because moving them can change audible timing.

Calculate nearest destinations with exact rational arithmetic. Exact halfway cases use a visible deterministic policy, defaulting to the earlier grid point, with later-point selection available. The preview shows every old/new row, movement distance in divisions and audio time, measure-boundary crossings, and objects that remain unchanged. Apply is one atomic undoable command; cancel or any rejected row leaves the document unchanged.

The requested grid must be representable by the global division count. If it is not, offer cancel or exact promotion to the least compatible global resolution before quantization; approximate rounding requires a separate explicit lossy policy and preview. Quantization never silently reduces the chart's global resolution.

For holds, support moving the head and tail to their nearest rows or moving the entire hold by its head while retaining exact duration. Reject or explicitly resolve zero/reversed holds and overlaps created by endpoint movement. Lane collisions, multiple exclusive timing values at one row, BGM occupancy, events crossing format/layout boundaries, and beat- versus audio-anchored data are handled through named policies rather than implicit overwrite. The BGM allocator may move a collision to the next ordered BGM lane while retaining the quantized row.

Conversion-time quantization calls this same transform on a temporary document and includes the row diff in `conversion_report_t`. The CLI therefore cannot use a separate rounding implementation from the editor.

### Keyboard lane editing and snap navigation

Define lane-key bindings in the active lane-layout profile and let the user override them. Bind defaults by physical keyboard position rather than the character produced by the current OS layout, while displaying the user's localized key names. This keeps the editing gesture stable across Windows, macOS, Linux, and non-QWERTY text input. Text entry, IME events, and key repeat must not accidentally place or move notes.

A bare lane-key press/release gesture creates or toggles the playable note at the edit row when there is no playable-note selection: an empty cell receives the armed tap, while an occupied editable tap or any point of an editable hold removes that whole note/hold. With a selection, the bare lane key moves all selected playable notes to that destination lane and keeps them selected. An unavailable destination or inclusive overlap rejects reassignment without changing the document or selection and reports the reason. Lane assignment adds no note-kind compatibility or lane-lock policy; selected timing and BGM objects remain selected and are ignored.

| Keyboard input | Result | Undo and rejection |
| --- | --- | --- |
| A lane key with playable notes selected | Move all selected playable notes to that lane and keep them selected. The key comes from the active lane profile. | One undo step. |
| Shift + a lane key | Move the first selected playable note in document order, preserve its exact position and hold length, and deselect it. Repeat the key gesture to move the next note. | One undo step per press. Unavailable destinations and inclusive overlaps leave the document and selection unchanged and report the reason. |

Delete/Backspace is an explicit editor command rather than a widget side effect. With no selection it removes the playable note on the active lane at the edit cursor, if present. With a selection it deletes every selected editable object in one previewed atomic command, including notes/holds and explicitly selected BGM, BGA, timing, bookmark, or section objects. Locked or non-editable members, stale IDs, and dependency/resource constraints reject the whole deletion and preserve the selection for correction; deleting notes never implicitly deletes their shared resources. Escape clears selection or cancels a pending gesture without deleting data.

Keyboard hold entry follows the StepMania editor gesture. Pressing and holding an unmodified lane key anchors the current snapped row; navigating later/downward makes it the head and extends the tail, while navigating earlier/upward makes it the fixed tail and moves the head upward by the exact cursor delta. Passing back through the anchor swaps endpoint roles continuously, and releasing at the anchor retains the ordinary tap-toggle/removal behavior. Releasing after a positive span applies the same tap-removal and touching/overlapping-hold union policy as pointer drawing in one command. Each physically held lane key owns its pending anchor so chord holds can be previewed together. Native repeat events for the held lane key must not create extra anchors or commits. Escape, focus loss, text/IME focus, a layout transition that removes the lane, or an incompatible collision cancels or rejects the preview without partial mutation. Pointer and keyboard hold entry use the same controller action, exact snap, collision normalization, layout, audition, and undo policy.

Provide these initial binding profiles:

- For single-play and compact split profiles, assign the left/only stage in lane order to the physical number row: `1 2 3 4 5 6 7 8 9 0`. Assign the right stage in double-play profiles to the row below: `Q W E R T Y U I O P`. Use only as many keys as that stage contains, including a scratch lane only where the lane profile places it in the ordered stage.
- For BMS 14K double play, use the requested interleaved BMS-editor layout: left stage `Q A W S E D R F`, right stage `H U J I K O L P`. These eight positions per side include the stage's seven keys and scratch according to the selected inside/outside-scratch profile rather than assuming scratch identity from the typed key.
- For BMSON-only Keyboardmania-style 24K, use a two-octave virtual-piano map in chromatic lane order: lower octave `Z S X D C V G B H N J M`, upper octave `Q 2 W 3 E R 5 T 6 Y 7 U`. The staggered letter/number positions visually separate natural and accidental keys.
- For BMSON-only Keyboardmania-style 48K, reuse the same 24-key piano map for the focused left or right 24-key stage. Dedicated commands switch or directly focus a stage, and the split-stage field makes the target visible before entry. This avoids assigning gameplay lanes to Space or Shift, which already have selection and move semantics. Users with a second keyboard, a MIDI keyboard, or a preferred full-key layout may bind all 48 lanes directly once multi-device input is available.

Show the active mapping as an optional key legend over the lane headers. Validate profiles for duplicate bindings within one active stage, conflicts with required editing gestures, inaccessible lanes, and platform-reserved combinations. Input commands operate on semantic lane IDs, so changing a key binding never remaps chart data.

Up and Down move the edit cursor by one active snap interval, crossing measure boundaries through exact rational position arithmetic and translating the shared chart viewport so every visible track stays under the full-width edit head. These navigation commands deliberately accept key-repeat events (unlike lane-note mutation): holding Up or Down advances rapidly at the configured/platform navigation repeat cadence, stops immediately on release/focus or text/IME capture, and never emits duplicate edit commands. On-screen Up/Down controls invoke the same repeatable commands while pressed. A pending Space range selection or physically held lane-key hold follows the repeated cursor positions, so the visible preview extends/contracts exactly as the grid indicates. This navigation does not silently move selected notes; note movement is an explicit command.

Measure paging is a separate command with a user-configurable positive measure count, defaulting to one. Page Up/Page Down invoke it on Windows and Linux; Option+Up/Option+Down invoke it on macOS. Paging preserves the cursor's exact fractional position within a measure when the destination geometry permits it, otherwise it previews or applies the documented nearest valid row policy, and clamps at the song boundary without wrapping. Holding the command begins repeat after one second and switches to a faster configured repeat interval after three seconds. The input controller uses a monotonic clock and ignores duplicate native key-repeat events, making the thresholds deterministic across platforms; release, focus loss, modal/text focus, or loss of the required modifier cancels the held state immediately.

Mouse wheels and precision trackpads scroll the chart viewport without moving chart data or quantizing the edit cursor. Consume SDL's precise floating-point deltas, preserve subpixel remainder between events, honor the OS natural/reversed direction information, and accept both axes. Vertical input scrolls chart time; horizontal input scrolls the pane under the pointer, including the independently scrollable BGM pane and wide variable-column fields. Shift may translate a one-axis wheel into horizontal scrolling where that matches platform convention, while the platform primary modifier plus wheel/trackpad performs cursor-anchored zoom. Sensitivity for coarse wheel notches and smooth scrolling is configurable separately.

Trackpad momentum remains viewport motion and can be interrupted immediately by direct pointer/keyboard navigation, focus loss, or opening a modal editor. The controller coalesces high-rate deltas per frame, clamps against content bounds without oscillation, and routes a gesture to the pane where it began until that gesture ends so crossing a divider cannot jump another pane. Do not infer note placement, selection, or timing changes from a scroll gesture. Tests use synthetic precise deltas and a fake frame clock rather than relying on host hardware.

Clicking the mouse wheel/middle button latches an autoscroll state for the pane under the pointer, aimed especially at BMS charts with many horizontally arranged BGM lanes. The latch records an anchor and keeps that pane captured after button release; pointer displacement from the anchor controls signed horizontal and vertical velocity with a dead zone and configurable maximum speed. Horizontal motion in a BGM pane changes only its independent horizontal offset. A second middle click, Escape, focus loss, modal opening, or an ordinary editing click cancels the latch immediately. Entering/cancelling the latch never selects, places, or edits an object, and its anchor/velocity indicator makes the active state visible.

Left and Right cycle backward and forward through a profile-configurable StepMania-style snap list. The initial list starts with the requested `1/4`, `1/8`, and `1/6` modes and continues with common straight and tuplet fractions. A snap `1/d` is available only when one standard-measure interval is integral at the chart resolution (`resolution % d == 0`); at 960, for example, denominators 4, 8, 6, 12, 16, 24, 32, 48, 64, 96, 192, 240, 320, 480, and 960 are exact. Cycling skips unsupported entries. If no next entry exists it keeps the current snap and gives visible feedback. Changing resolution must preview any required active-snap fallback along with positional quantization; it cannot leave the editor on an inexact snap.

Modifier dispatch should follow the useful structure observed in the [uBMSC/pBMSC input handlers](../../references/pbmsc-input-handling.md): resolve the focused editing context and exact global shortcuts first, then lane assignments, then modifier-insensitive navigation commands. Sample modifiers from the key event, suppress mutation on auto-repeat by default, and keep command construction independent from Nuklear rendering callbacks.

### Command registry and keyboard shortcuts

Expose editor operations through one backend-neutral command registry rather than hard-coding behavior directly in Nuklear or SDL callbacks. Every command has a stable ID, localized display name, category, current/default shortcut chords, focus scope, enable/checked state, and a typed invocation that reaches the same controller/undo boundary as menus and toolbar buttons. Shortcut profiles are user-remappable and serialized separately from chart data. The dispatcher resolves modal/text/IME focus first, then exact global/workspace commands, active-tab tools, and lane bindings; it diagnoses conflicts and never lets a hidden tab or auto-repeat invoke a mutation accidentally.

Seed the registry with discoverable defaults for ordinary document and navigation work, including **New Project**, **New Chart**, previous/next bookmark or section boundary, previous/next snap, undo/redo, delete, selection commands, transport, and timing tools. Use the platform primary modifier for document commands; reserve `Ctrl/Cmd+Shift+N` as the initial New Chart chord unless a platform binding overrides it. Map `F1`, `F2`, and subsequent function keys to the visible workspace tabs in their stable order, with the active tab shown in menus and with remapping available when the OS reserves a key. Previous/next marker commands consume the exact marker-navigation service and must preserve the distinction between beat- and audio-time cursors rather than guessing a conversion.

Map `Ctrl/Cmd+1` through `Ctrl/Cmd+9` to the corresponding visible semantic-layer palette slots. The shortcut arms or toggles the layer-selection/painting target according to the active tool; the UI must show which stable layer ID each numbered slot currently addresses, and palette reorder, hidden/locked layers, or fewer available slots must update or disable the command deterministically. Do not persist a positional digit as the note's layer identity. Provide commands for clearing the active layer target and for applying/removing/toggling the armed layer across the current selection through the atomic semantic-layer command.

Include a dedicated hitsound/keysound painting command and shortcut slot in the registry, even if its default chord remains profile-dependent to avoid lane-key conflicts. Entering the mode visibly arms one resource or BMSON slice/layer set; click or bounded drag previews and assigns that sound reference to existing notes or BGM cells through one atomic paint transaction. It must not silently create, move, or delete notes unless the explicitly selected combined placement tool says so. Escape exits or cancels the paint gesture, locked objects remain unchanged, missing resources are diagnosed, and audition uses the same exact slice/layer playback path as the resource browser.
