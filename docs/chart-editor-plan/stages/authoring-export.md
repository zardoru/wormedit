# Implementation stages 3–5: authoring and export

[Back to the implementation-stage index](../stages.md).

## 3. Core editing

- The bounded atomic note-placement paint controller is now wired into Compose as an explicitly armed pointer tool. Its scene preview uses the same zoom/scroll/layout geometry as notes, distinguishes green additions, coral tap removals, and amber collisions with holds, mines, or other notes, and cancels safely across revision, focus, mode, capacity, modifier, and shortcut boundaries. This does not yet implement hitsound/keysound assignment painting, semantic-layer painting, or select-and-drag movement.
- Implement mouse and Space range selection, first-class snapped mouse note placement, bidirectional Alt/Option press-drag hold entry and atomic selected-note duration-delta resizing, hold-to-tap contraction at zero length, StepMania-style occupied-note removal and overlapping-hold union, single-note/selection deletion, paint drag, object hover states and type-specific double-click editors, global division and exact snap/grid policy, repeatable Up/Down snap navigation, Left/Right supported-snap cycling, configurable cross-platform measure paging with timed repeat/acceleration, note and hold creation, move/resize/delete, and note labels. Every captured transform supplies exact valid/destructive/invalid ghost geometry from its command proposal. The headless mouse/Space selectors now share typed, explicit note/BGM/timing/BGA scopes and indexed beat-anchored markers/sections; typed hover/tooltips and guarded same-object double-click edit requests are implemented. The Compose frontend now provides snapped click toggling, an explicitly armed bounded note-paint drag with valid-add, tap-remove, and invalid-collision previews, Up/Down movement, selection/cursor deletion, Alt/Option-drag hold creation or existing-note duration resizing with selected-note deltas and hold-to-tap collapse, empty-field rectangle selection with replace/add/toggle modifiers, and tap-anchor/tap-tail Space selection with visible previews. Holding Space while navigating now commits that preview on release, and its anchor and tail rows flash. The shared hold controller now keeps the pressed row as its anchor, moves the head across it in either direction, contracts to a tap at equality, removes covered ordinary taps, and unions touching/overlapping ordinary holds atomically while rejecting special or metadata-bearing notes. Its revision-bound renderer proposal now renders the exact normalized head/body/tail result and subdues every note that the commit would remove, including transitive cross-measure unions; zero-length occupied-note removal intentionally has no addition ghost. Dragging any selected playable note now moves the complete playable-note selection vertically by one snapped delta, preserving lanes and durations; stale, out-of-chart, lane-layout, and collision proposals reject atomically while origin and destination ghost geometry remain visible. The Compose toolbar now exposes the bounded revision-checked note-label command for the current explicit selection: Apply retains even an empty authored UTF-8 label, while Clear removes it atomically. Lane-changing/mixed-object movement, snap cycling, held navigation repeat, accelerated paging, hover/property editors, and pane-specific horizontal geometry remain frontend work.
Navigation status: Left/Right already cycle exact supported snap fractions. Compose now routes repeat-free Up/Down and Page Up/Down presses/releases, plus held Step up/down and Page up/down toolbar controls, through a backend-neutral monotonic-clock navigation controller: it emits once immediately, repeats after one second, accelerates after three seconds, bounds delayed-frame bursts, and cancels on release/focus/context changes. Page actions retain fractional rows across unequal measure capacities using nearest-row rounding with midpoint ties toward the earlier row, clamp at chart bounds, and keep the cursor visible. macOS Option+Up/Down provides the page mapping as well.

Lane-move status: dragging a selected playable note across Compose lanes now applies the same display-column delta to the complete playable-note selection. The atomic proposal validates every destination lane through layout changes, rejects collisions and missing columns, and renders each ghost in its final lane. Mixed-object movement remains pending.

Hover status: Compose now feeds idle in-field pointer coordinates through the revision-bound indexed note hover query. The matching note endpoint or hold is highlighted and its stable tooltip is shown in the field; hover is cleared outside the field, across revisions, and while a captured edit gesture is active. Generic property editors remain pending.

Double-click status: the existing SDL double-click capture now reaches Compose as a dedicated note action. Double-clicking a note selects it, loads its authored label into the existing label field, and focuses that field for editing; ordinary single-click tap toggling remains unchanged. Broader type-specific property forms remain pending.

Viewport autoscroll status: the Compose frontend now captures a middle-click inside the chart field as a visible, revision-safe autoscroll latch. Pointer displacement drives the tested two-axis controller on the frame clock, scrolling the chart without creating edit commands; ordinary Compose input, wheel input, focus loss, tab changes, and a second middle-click cancel it deterministically. Trackpad momentum and the independent BGM pane still require their later frontend surfaces.

- Implement shared/per-difficulty metadata editing and ordered target-format fields through the document command boundary. Bounded revision-checked commands now set normalized song/chart fields and optional exact difficulty ratings, and insert, replace, or erase duplicate format-specific fields atomically while keeping imported provenance positions aligned; the Metadata pane exposes those edits for one selected difficulty and generic format fields. Add always-visible typed default fields for the selected format/mode, per-chart key-count/profile selection through previewed lane migration, transactional song-file copy/relink drag targets for project and export directories, and one cross-cutting Audio and synchronization group. Compose's Offset/Waveform-drag mode and Metadata's waveform/numeric control share one sample-frame-exact ghosted offset controller rather than writing format-specific fields. Inheritance/override controls, multi-difficulty batch edits, and the remaining typed per-format controls/validation remain.
- Implement previewable exact row quantization using active-snap or numeric standard-measure/per-measure divisions, deterministic ties, configurable row/event and hold scope, collision diagnostics, optional exact resolution promotion, and one atomic command.
- Implement profile-driven lane-key tap and StepMania-style press/navigate/release hold entry in either direction, occupied-note removal, overlapping-hold union, chord-hold previews, whole-selection lane assignment, and successive first-note Shift + lane move/deselect/audition behavior, including the on-screen binding legend and 48K stage focus. The headless controller and Compose frontend now implement bound lane-key press/move/release tap-or-hold entry plus atomic whole-selection and deterministic Shift-successive lane assignment, selection consumption, and an audition request. Keyboard hold navigation now uses the same anchored moving-head and collision/union proposal as pointer entry; a lane-key press on one occupied ordinary tap or hold removes that whole object, and its following release is inert. Chord/multi-key hold previews are explicitly unsupported for now; the full binding legend and 48K focus remain.
- Implement native rich copy/paste plus fixture-backed BMSE and iBMSC clipboard adapters with previewed lane/resource/conflict mapping.
- Implement sample/BGM/BGA resource import and create/assign/replace placement commands, referenced-resource deletion protection, usage navigation, deterministic BMS identifier allocation, and the compact placement toolbar's create-only auto-increment state machine with stable eligible ordering and explicit exhaustion policy.
- Implement semantic-layer palette editing, note painting/assignment, filters, solo/lock behavior, and native-project persistence. Revision-checked commands insert, update, delete, and reorder named colored semantic layers and atomically assign/remove/toggle them across bounded explicit note selections. Locked layers reject membership mutation and deletion, and in-use deletion requires an explicit bounded membership removal. The 50,000-note assignment path is indexed rather than quadratic. Compose now exposes the bounded palette, target selection, creation, rename, arbitrary RGBA editing, reorder, visibility, lock, solo, require/exclude filters, select-by-layer, selected-note membership operations, and captured membership painting. The color picker keeps a frontend-local draft and publishes one exact 8-bit RGBA command only on Apply, so dragging does not flood history. Revision-cached membership counts make destructive scope visible; ordinary Delete retains its refusal for populated layers, while the separately labeled **Delete + unlink** action removes every membership and the layer in one undoable transaction. The nine physical palette slots now page over a pure bounded core projection: Previous/Next exposes every visible layer, local numbered shortcuts follow the displayed page, a newly selected hidden or off-page stable ID is revealed automatically, ordinary browsing retains the current target, and the page clamps after document edits.
- Implement measure insertion/removal, exact length editing, global redivision, time-signature selection, and column-layout changes. A revision-checked measure command boundary now inserts exact authored measures, updates exact length/meter definitions, and removes empty unreferenced measures while preserving stable measure IDs and repairing BMS measure-number projections atomically. UI controls, nonempty-measure migration, global redivision, time-signature helpers, and column-layout changes remain.
- Implement BPM and SV event editing, including StepMania speed transitions. Revision-checked command boundaries now insert, update, and delete exact BPM, scroll/SV, speed-transition, stop/delay, and warp events through shared history. They preserve identity/provenance on updates, assign deterministic source order on inserts, retain same-row ordering, validate source-specific pause units, and repair BMS timing projections on deletion. A transient typed pseudo-note controller prepares BPM, scroll/SV, speed, stop, delay, warp, kiai, and anchor changes at exact snapped rows or loads an existing stable event, then confirms each through one existing history command without creating playable notes. The Timing pane renders bounded BPM, Scroll/SV, SPEEDS, Stop, Delay, and Warp lanes; double-clicking an empty row stages revision-guarded insertion, while double-clicking an existing marker loads its fixed-position exact value and only Apply mutates it. BPM staging is now decimal-first and parses directly to the exact core rational without binary floating point; advanced numerator/denominator access remains available, a displayed approximation never quantizes a derived non-terminating value, and `-1`/`+1` steppers adjust the authoritative rational exactly with checked positive-range/overflow rejection. Existing edits retain stable IDs, provenance, authored pause units, warp encodings, and deterministic same-row target selection. The insertion snap is a fixed quarter beat with a whole-measure fallback for incompatible resolutions. Exact evaluator-backed single and bulk SPEEDS spans retain fractional row/time endpoints, clip at replacement or chart end, distinguish beat and seconds clocks across stops and warps, and draw the hovered marker's affected area with a light overlay; the 50,000-span bulk fixture remains within the 125 ms budget. Marker dragging/deletion, active-grid/viewport-aligned navigation, kiai/anchor widgets, and meter-event insertion remain.
- Implement ordered tag editing, bookmark/section creation and navigation, and kiai region editing with retained timing-effect bits. Revision-checked commands now provide beat/audio-time bookmark and section CRUD plus kiai CRUD while retaining unrelated timing-effect bits. Song metadata exposes bounded ordered tag occurrences with duplicate-preserving add, edit, remove, and Up/Down reorder controls; Apply publishes the exact list as one undoable transaction. A bounded revision-aware navigation service finds strict previous/next bookmark or section boundaries in exact variable-measure rows or signed audio milliseconds, and resolves beat-anchored section selection spans while requiring an explicit timing projection for audio-time sections. Compose exposes Previous/Next marker controls only when beat-anchored bookmarks or section boundaries exist; they invoke the same registered commands as keyboard shortcuts and preserve strict variable-measure cursor navigation. Backend-neutral selectors independently show the first 64 beat and audio-time bookmarks/sections by stable ID. Beat bookmark controls add, rename, move to the exact cursor, and delete; beat section controls add from the last committed non-empty area/Space interval (falling back to one active snap at the cursor), rename, move either boundary to the exact cursor with core ordering validation, and delete. Signed-millisecond audio bookmark/section controls add, update label and exact position/span, and delete without pretending those values already have beat-grid coordinates. The controller owns and normalizes retained beat spans so future frontends consume identical coordinates. Every successful edit uses shared undo history. Audio-time-to-beat projection/navigation and Timing-pane controls remain.
- Implement custom BMS channel-map editing with migration preview and validation.
- Implement manual/seeded BMS branch projection and tree-aware selection safety. Exact-provenance replacement, insertion after a source-verified statement, and deletion of an inactive raw branch statement are implemented as pure format proposals with atomic rejection for active, stale, structural, ambiguous, malformed, or oversized edits. Core command adapters now revision-check those proposals and publish them through shared document history, so each operation participates in dirty tracking and undo/redo while retaining typed BMS diagnostics. Deletion supports IF/ELSEIF/ELSE/CASE/DEFAULT leaves and preserves an empty leaf when its enclosing control blocks remain valid. Inactive insertion and deletion currently require one-chart BMS source documents; explicit source-chart identity across multi-chart projects remains to be designed. The workspace now exposes a bounded renderer-neutral outline of the complete retained tree, marking the imported active and selected paths and reporting stale choices or row/text truncation. Manual/seeded selection remains pending until a pure reprojection API can update semantic chart payloads and inspector state together; the writer already preserves and emits the complete retained tree. The outline authoring UI, branch creation/removal/reordering, selected-leaf/common insertion scopes, and branch moves/replication remain.
- Implement Ctrl-drag local beat fitting, last-BPM interval fitting, locked anchors, optional waveform-onset snapping, and atomic preview/commit behavior. Exact sample-frame timing-anchor CRUD, including the locked flag and coincident anchors, now participates in shared revision/history validation. The headless last-BPM interval fitter solves to an exact audio frame across pauses and warps, rejects movement of locked anchors, and commits its revision-bound preview as one undoable BPM edit; Compose now offers beat-rail drag handles for this interval fit, with a fixed waveform, proposed beat grid, BPM and target-frame preview, and cancel/commit through the revision-bound transaction. Local Ctrl-drag fit, downstream locked-anchor compensation, richer affected-note/event previews, and waveform-onset snapping remain.
- Add command-based undo/redo, dirty tracking, clipboard operations, and live validation; expose document revisions to the stage-one autosave/recovery service. A bounded backend-neutral registry now models stable command metadata, USB-HID shortcuts, primary-modifier mapping, focus precedence, conflicts, repeat policy, and standalone remappable profiles, with seeded new-chart, undo/redo/delete, bookmark, workspace-tab, semantic-layer, and hitsound-paint commands. Bounded profile-file loading distinguishes missing, malformed, oversized, and I/O failures; saving flushes a same-directory temporary before atomic replacement, and SDL resolves a platform preference path. The SDL frontend now submits bounded same-window physical-key batches with text/IME/lane focus, the application applies the optional profile at startup, and runtime registry dispatch reaches existing history/workspace/interaction controllers for undo/redo/delete, selection, exact marker jumps, snap changes, workspace tabs, timing lock, and semantic-layer targeting/membership. Unsupported seeded commands are disabled rather than simulating behavior. Preference-change saving, remapping and command-menu UI, plus the remaining disabled controllers, remain.
- Define timing-edit behavior for beat-anchored and time-anchored notes.

Exit condition: a chart can be authored and recovered after restart without exporting it.

## 4. Audio clips and BMSON authoring

- Build an asset browser and sound-channel waveform view that displays specification-derived slice boundaries and provides audition controls. The headless path now carries revision-bound note/BGM activation intent through Compose, owns a bounded registry of real normalized decoders, resolves exact BMSON event links against authoritative decoded-source geometry, and prepares bounded transport clips without replacing a live audition on stale or resolution-failed requests. A generation-gated lookahead pump plans every distinct block before decoding, enforces fixed window/block ceilings, reuses cached blocks, and feeds the headless mixer across source-block boundaries without underrun. A session owner primes before activation, separates off-realtime refill from cache-only rendering, advances one monotonic output-frame cursor, preserves a live generation on pre-start validation failure, and guarantees hard Stop silence on the next render. The application resolves startup-project audio paths only against the explicit project directory and consumes each activation request once; SDL device/callback/stream-flush integration, dynamic registry reconciliation after document replacement, the browser, and waveform controls remain.
- Add the multi-marker razor mode over the timing-aligned channel waveform. Snap clicks to the active divisor, default to continuation, use Shift-click for restart, preview all edits, and commit/cancel the marker set atomically.
- Assign BMS keysounds and BMSON sound-channel events to playable notes or BGM events.
- Edit BMSON restart/continuation state and event positions, recomputing derived slices as timing changes.
- Import and preserve BMSON channel/continuation provenance; export valid BMSON 1.0 sound channels without fade, gain, pan, or non-standard slice fields.
- Add the specified collision/layering behavior, open-ended final slices, source replacement/relinking, and missing-file diagnostics.
- Let an exact area/Space-selected chart interval plus a caller-supplied duration generate a transactional `preview.ogg` through the shared preview mixer, with async progress, cancellation, deterministic duration/trim/fade-out behavior, and atomic file publication.

Exit condition: the mixed-sound and continuation fixtures round-trip semantically, and a long source can be sliced into a newly authored BMSON chart without rendering separate audio files.

## 5. Format export passes

- Implement the shared conversion request/pipeline and expose it through both in-editor conversion preview and the headless rdconverter-style CLI. A detached in-memory preparation service now dispatches paired native-project, BMS-family, SM/SSC, osu!mania, and BMSON writers, enforces typed policy/loss/output limits, groups or splits artifacts by target, and re-import-validates the complete set before returning any output. Filesystem publication, preview UI, and CLI wiring remain.
- Implement and validate SM and SSC export as authoring peers, using explicit syntax compatibility profiles. A bounded paired foundation now handles multiple difficulties, ordered retained metadata, common 3/4/5/6/7/8/10-column step types, exact note grids and core note kinds, signed OFFSET, BPM/stops/delays, native and legacy warps, SCROLLS, and SPEEDS. SSC preserves shared song timing versus chart timing and maps `CHARTNAME` plus per-chart `CREDIT`; SM maps global `CREDIT` to chart authors and rejects conflicting author edits. The `native_warps`, `legacy_negative_bpm`, and `legacy_negative_stop` choices assert source/target timing syntax, not a particular release's full behavior; an explicitly selected source profile rejects mismatched native or legacy warp syntax. A v0.83 SSC fixture exercises broader song/chart metadata while retaining format-only fields; `.sm` rejects native WARPS and nonempty SCROLLS/SPEEDS instead of emitting fields standard SM loaders ignore. Unsafe metadata and unfaithful note kinds reject, while editor layers decay to their gameplay notes and bookmarks are diagnosed omissions. Player/version compatibility evidence and broader metadata inventories remain.
- Complete paired readers and writers for every advertised format profile and gate support claims on semantic export/re-import fixtures.
- Add native-warp and StepMania 3.9 negative-BPM export strategies selected by target implementation, with semantic re-import verification.
- Implement the osu!mania reader's measure-rewiring pass and then export with timing-point, meter, and sample mapping; semantic reload must reproduce both absolute object times and effective measure-line placement. The bounded paired codec handles and tests every integer key count from 1K through 18K with dynamic layouts and every lane round-tripped, source-ordered uninherited phase resets, inherited SV, half-open measure ownership, directional near-line suppression, omitted-first-barline geometry with piecewise-tempo row integration, notes/holds, metadata/tags/bookmarks/kiai/resources, and retained source times. Standard General, Editor, Metadata, Difficulty, and Colours fields round-trip under independent field-count and byte caps. The writer emits deterministic integer-millisecond Mode 3 files with timing/meter/SV/effects, samples, BGM, background, video, and representable embedded storyboard content; it rejects storyboard export from multi-chart songs until storyboard-to-chart ownership is modeled. Unsupported transformations reject explicitly. Broader implementation profiles and version-specific metadata fixtures remain before it is advertised complete.
- Implement selected BMS dialect exports with keysound/resource allocation, custom channel maps, default full-tree emission of every retained branch/control statement, and explicit active-projection flattening. Provenance-backed active-branch metadata, WAV/BMP paths, effective measure ratios, notes/holds, BGM/BGA slots, direct and extended BPM events/declarations, and uniquely owned STOP pauses are editable in place; inactive raw branch statements support exact-provenance replacement, insertion into, and deletion from an inactive leaf without flattening. Inactive insertion and deletion are currently restricted to one-chart BMS source documents. Active projection now flattens multiple BPM changes and BMS-tick pauses through channels 08/09 when their values have exact terminating-decimal spellings. Cross-measure moves, occupied-slot collisions, shared timing declarations, structural branch changes, and timing/event classes without import projections remain source-backed and reject ambiguous edits.
- Implement Standard MIDI export from semantic lane maps, with explicit musical/performance timing policies and exact-or-diagnosed PPQ conversion.
- Add per-target preview, warnings, and round-trip regression tests.

Exit condition: the supported feature matrix has no unclassified losses and exported fixtures reload to the expected semantic documents.
