## 0. Fixtures and capability inventory

- Add a Catch2 v3 test harness before expanding the model: top-level `include(CTest)`, a `BUILD_TESTING`-guarded test directory, `Catch2::Catch2WithMain`, and `catch_discover_tests(... DISCOVERY_MODE PRE_TEST)` registration visible to `ctest -N`.
- Pin the BMSON 1.0 specification as the normative slicing fixture source and record the inspected BmsONE revision as UI/reference evidence. Add the published multi-pulse slicing example and all specified edge cases as expected semantic results before implementing the writer.
- Assemble small, redistributable fixtures for BMS, BME/BML, SM, SSC, osu!mania, and BMSON 1.0.
- Require paired reader/writer fixtures for every advertised format profile; no import-only profile counts as supported.
- Include awkward cases: default 960- and alternate 192-division grids, supported/unsupported snap fractions, events requiring global division-count promotion, ambiguous time-signature interpretations, fractional measure lengths, column-count changes, stops/delays/warps, negative or zero scroll where legal, transitioning speeds, mixed BMSON sounds, continuation slices, holds, used/unused/missing WAV/BMP/sample/BGA resources, repeated BMS BGM lines with structural `00` slots, custom/unknown BMS channels, nested BMS random/conditional/switch trees, osu! tags/bookmarks/kiai transitions, and streamed music.
- Add exact channel-map fixtures for every initial common BMS/BME/PMS layout and its corresponding visible/invisible/LN/mine families, including ambiguous combinations that must remain custom rather than being misdetected.
- Add paired StepMania fixtures for native warps, 3.9-style negative BPM, negative-stop warps, stops within warp spans, same-beat timing commands, and target-profile export/re-import expectations.
- Add BMS command-memo fixtures for repeated BGM lines, measure ratios, BPM/STOP collisions, STOP units, and selected compatibility-profile differences.
- Add BMS control-flow fixtures for selected and fixed random values, IF/ELSEIF/ELSE groups, SWITCH/CASE/DEF fallthrough and SKIP, mixed nesting, common/orphan content, and malformed recovery profiles.
- Add encoded BMS fixtures for UTF-8, CP932/Shift-JIS, EUC-KR/CP949, and Windows-1252, including ambiguous and invalid inputs.
- Capture and document native clipboard samples from BMSE and iBMSC versions in scope, including their behavior for BGM, long notes, BPM, STOP, and free-grid positions. Source-derived payloads for BMSE 3.0/legacy and iBMSC 3.5.5.16 normal/xNT are checked in; runtime captures remain optional confirmation.
- Add matched SM/SSC fixtures for every timing feature both formats may express, so support is based on observed parse/write behavior rather than an assumed format hierarchy.
- Add short and long MP3/Ogg fixtures and verify bounded-memory sequential decode, seeking, waveform completion, cache reuse, and click-preview on Windows, macOS, and Linux.
- Document the exact data currently exposed or discarded by `libotoworm` for each fixture as reference evidence.
- Assign every supported format feature to a wormedit-owned byte-preserving codec/timing component. Do not extend or link `libotoworm` as the implementation path.

Exit condition: the initial import/export capability table and expected semantic result for every fixture are checked in.

Verified by: `ctest --test-dir build -R 'Stage 0'` plus `ctest --test-dir build -R '^audio\.'`; a fixture without a checked-in expected result is a failure.

## 1. Editor document and timing engine

- Add stable IDs, a default-960 chart division count, layout/stage segments, custom channel maps, a lossless BMS control tree and branch membership, a semantic note-layer palette, tags, navigation markers/sections, rational local positions, measure chunks with editable lengths, typed timing/scroll/kiai/BGA events, timing anchors, ordered BGM source lanes, notes, audio/visual assets, clips, and a shared resource catalog with target provenance.
- Add data-defined built-in BMS lane profiles for the command memo's common 5K/7K/10K/14K/PMS and special layouts, with confidence-based detection and lossless custom-map fallback. Add Keyboardmania-style 24K/48K only as BMSON generic-key profiles.
- Add exact signed beat-zero/audio offset data and apply it consistently in timing, waveform, preview, and conversion.
- Add exact global redivision operations, time-signature suggestions/disambiguation, and prefix indexes for global position lookup.
- Implement beat/pulse, chart-time, and audio-time conversion with tested boundary behavior around BPM changes, stops, delays, and warps.
- Store canonical exact-beat warps and legacy negative-BPM/negative-stop provenance; add profile-driven import normalization and warp export policies.
- Replace the lossy `Chart` conversion with an importer that reports preserved, approximated, and dropped fields.
- Add byte-oriented BMS ingestion, encoding detection/override, UTF-8 normalization, original-byte provenance, and an iconv-compatible conversion interface.
- Implement wormedit-owned BMS control-tree parsing/evaluation with fixed rolls, explicit ends, mixed nesting, switch fallthrough, and caller-selected deterministic projections without discarding the tree; use the `libotoworm` audit only as a regression reference.
- Establish bounded deterministic native project serialization, asset references, generator-recipe records, and a migration/version field. The version-1 whole-document JSON codec plus validated atomic primary publication are implemented; filesystem packaging and migrations remain.
- Serialize several ordered difficulties, shared/per-difficulty/format-scoped metadata with explicit inheritance, and named single-file or multi-file output groups.
- Add the five-minute native-project autosave coordinator, validated atomic `.bak` envelope, optional checksummed command journal, startup recovery scan, and platform crash-marker backend described in the recovery contract. The bounded checksummed envelope, atomic replacement, monotonic five-minute coordinator, startup comparison, content-ticket revalidation, guarded recover/inspect, create-only save-as, recoverable quarantine execution, generation-checked controller, explicit frontend recovery panel, and bounded periodic application autosave loop are implemented. Startup resolves/creates the SDL per-user recovery directory and scans its bounded regular-file contents along with the primary, adjacent backup, and caller-supplied recovery artifacts; it loads only a validated primary and retains candidates for explicit recovery. Autosave publication runs off the frame thread with one in-flight immutable snapshot, retry backoff, and recovery-session handoff protection. The journal and crash-marker work remain.
- Define serialized, remappable input profiles using physical key positions, including all initial single-, double-, 14K-, 24K-, and 48K-stage mappings.

Exit condition: fixtures import into an inspectable document without losing data required by their intended round trip.

Verified by: `ctest --test-dir build -R 'round.?trip|reimport|^core\.'`; every fixture under `tests/fixtures/` must be named in a passing test.

## 2. Read-only chart view and streamed waveform

- Replace the scaffold's direct Nuklear calls with backend-neutral workspace/tab view models and typed UI actions, then put Nuklear lifecycle, widget composition, styling, and third-party types entirely in its frontend adapter. Nuklear lifecycle, input, widgets, and responsive workspace-shell composition now live under `src/ui/nuklear`; `main` translates the real workspace controller view into a private scalar view/action contract and dispatches revision-checked tab changes. The Compose pane currently renders bounded scalar projections of the field scene with layout bands, lanes, exact grid lines, notes/holds, selection styling, and cursor geometry. It retains chart/revision-stamped cursor, selection, zoom, and scroll state; routes click, lane-key, Alt/Option-drag, deletion, undo/redo, page-scroll, zoom, reset, vertical coarse/smooth wheel scrolling, and pointer-anchored primary-modifier wheel zoom through the headless interaction controller; and cancels captured gestures on focus/capacity loss. Refactor that wide note-only surface into the compact hybrid Compose layout: content-sized active tabs and menus, centered bounded-width playable columns, square indexed default notes, shared full-width edit head, measure-number and toggleable timing rails, right-side BGM tracks, collapsible sound controls, mode-default up/downscroll, and compact conditional recovery/status chrome. A simulated frontend event-queue harness, reusable double-click-select-all text fields, horizontal BGM-pane routing, momentum/autoscroll wiring, and the remaining interaction modes are still pending.
- Add a checked single-value CMake UI-backend selection and private frontend alias target; keep wxWidgets, ImGui, and Clay adapters optional until a replacement or performance spike is needed. `WORMEDIT_UI_BACKEND` and `wormedit::ui_frontend` now provide this checked configure/link boundary, with an architecture test protecting headless sources. Once the Stage 3 surface behavior settles, partition the Nuklear adapter by pane and shared widget/input responsibility behind the unchanged boundary so its implementation size does not force unrelated UI state into one translation unit.
- Build the shared song-workspace tab controller and Setup, Metadata, Timing, Compose, Audio/Slices, and Compare/Validate shells with retained transport/difficulty context and isolated focus handling. Keep the Storyboard tab as a disabled/placeholder entry until stage 7 if helpful for layout stability. The bounded backend-neutral controller exposes all seven tab views, stable difficulty and comparison-pane selection, shared transport and command-history summaries, per-tab logical focus, and the disabled Storyboard placeholder. Its Metadata view exposes bounded ordered shared/per-chart target-format fields and source identities; the Nuklear pane edits shared title/artist/tags, selected-difficulty name/author/exact optional rating, and generic duplicate-preserving format fields through revision-checked actions. - Build the fixed left measure-number/timing rail with measure/meter, BPM, scroll/SV, speed, stop, delay, warp, kiai, anchor, and section lanes; the compact variable-column note field with square indexed defaults plus skin/snap views, continuous/split-stage presentation and layer coloring; synchronized zoom-aware measure/beat/active-snap grid lines in both Compose and Timing; the immediately adjacent independently horizontally scrollable right BGM pane; timing markers; and a read-only BMS branch outline driving the active selected-leaf projection.
