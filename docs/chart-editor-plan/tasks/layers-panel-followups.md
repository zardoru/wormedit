# Layers panel follow-ups

[Back to task cards](../tasks.md).

User request (Zar, 2026-11-15): four future features for the semantic-layer ("Layers") dock panel. They are recorded as cards only; none is started. Shared facts from the current code:

- The panel is `worm_ui_nuklear_render_compose_layers` in `src/ui/nuklear/compose/compose_layers_panel.cpp`. It lists a **windowed** projection (`semantic_layer_first_row`, `semantic_layers`, `semantic_layer_total_count`, bounded by `semantic_layer_window_limit`), not the whole catalog, because charts may hold up to 100,000 layers.
- A row's `selected` flag means "this layer is the paint/assign **target**" (single choice, plus the "No layer" row). There is no multi-row selection yet.
- Layer actions are `WORM_UI_COMPOSE_ACTION_*` values (`src/ui/frontend/actions.h`), each handled by a validated action in `src/sys/compose/actions/compose_actions.cpp`. Core edits live in `include/wormedit/core/semantic_layer_editor.h`. Delete already has two forms: plain Delete (rejects populated layers) and "Delete + unlink" (`semantic_layer_delete_options_t::remove_from_notes`).
- The Layers panel is reachable today from View > Layers panel (`src/ui/nuklear/app/menu_bar.cpp`, command `view.open_layers`, Primary+L) and from the right dock strip icon (`src/ui/nuklear/dock.cpp`). The Compose toolbar (`src/ui/nuklear/compose/compose_toolbar.cpp`) has only the Layer paint tool.
- One layer per note stays (open question 10); a note belongs to at most one layer, so merge never has to resolve double membership.

## T-787 Multi-select layers and merge them

- **Status:** ready (not started; recorded 2026-11-15)
- **Outcome:** The user can select several layer rows (Ctrl/Cmd-click toggles, Shift-click selects a range) and run "Merge into..." from the row menu. The selected layers' notes and BGM events move into one destination layer in one Undo step, and the emptied source layers are deleted in that same step.
- **Read first:** AGENTS.md; this card's shared facts; `include/wormedit/core/semantic_layer_editor.h`; `src/core/semantic_layer_editor.cpp`; `src/sys/compose/actions/compose_actions.cpp` (layer delete, reorder and membership actions); `src/ui/nuklear/compose/compose_layers_panel.cpp`; `src/ui/nuklear/compose/compose_state.h`.
- **Files owned:** `include/wormedit/core/semantic_layer_editor.h`; `src/core/semantic_layer_editor.cpp`; `tests/core/semantic_layer_editor_tests.cpp`; `src/ui/frontend/actions.h` (appended action kind and ID list payload); `src/sys/compose/actions/compose_actions.cpp` (merge action only); `src/sys/compose/views/compose_view.h` (multi-selection projection); `src/ui/frontend/compose.h` (view field); `src/ui/nuklear/compose/compose_layers_panel.cpp`; `src/ui/nuklear/compose/compose_state.h`; `tests/ui/` (one new event-harness case file); `tests/CMakeLists.txt` (dedicated registrations only); this card.
- **Steps:** 1. Decide where the multi-selection lives. Recommended: ephemeral chart-scoped UI state of stable layer IDs, dropped on chart/project change and revision mismatch, separate from the single paint target. 2. Add a core merge edit: validate every ID, require all sources and the destination unlocked, reassign note and BGM memberships to the destination, delete the sources, one transaction. 3. Add the guarded action and the row selection gestures; make the menu entry show the count and the destination choice (default: the first selected layer in chart order; explicit pick via a submenu). 4. Verify selection across scrolling of the windowed list, then core, action and event-harness cases.
- **Invariants:** Stable layer IDs and the expected-revision guard. Merge never edits gameplay fields. The destination keeps its name, color and order. One note stays in one layer. Sound defaults that point at a source layer are retargeted to the destination so no dangling layer ID remains. Selection never changes the paint target and never edits the chart. One successful merge is one Undo record; reject or no-op creates none. Selection survives list scrolling, so it must be stored by ID, not by window row.
- **Reject/failure behavior:** Fewer than two layers, a duplicate or missing ID, a locked source or destination, a stale revision, an active gesture, or exceeding the configured object cap rejects the whole merge atomically with feedback. Selected rows that vanish (deleted elsewhere) drop out of the selection instead of failing.
- **Verify:** Focused core cases (merge, locked, duplicate, sound-default retargeting, Undo/Redo); action cases; event-harness cases for Ctrl/Shift selection over a scrolled list; GATE; documentation checks.
- **Out of scope:** Merging across charts; allowing a note in several layers; renaming or recoloring the destination as part of merge; drag-and-drop merge; multi-select for other panels.
- **Open questions for Zar:** Is "destination = first selected" acceptable as the default, or should the user always choose? Should the merged sources be deleted (recommended) or kept empty?

## T-788 Filter the layer list by name

- **Status:** ready (not started; recorded 2026-11-15)
- **Outcome:** A search field in the Layers panel header narrows the list to layers whose name contains the typed text (case-insensitive). The "No layer" row stays pinned. A clear control restores the full list. The count in the header shows "matches of total".
- **Read first:** AGENTS.md; this card's shared facts; the Sounds panel search field (`src/ui/nuklear/compose/compose_sounds_panel.cpp`) as the nearest existing filter; `src/core/semantic_layer_editor.cpp` (palette and window projections); `src/ui/nuklear/compose/compose_layers_panel.cpp`.
- **Files owned:** `include/wormedit/core/semantic_layer_editor.h` and `src/core/semantic_layer_editor.cpp` (filtered window projection); `tests/core/semantic_layer_editor_tests.cpp`; `src/ui/frontend/actions.h` and `src/ui/frontend/compose.h` (filter text in the window request, filtered total in the view); `src/sys/compose/actions/compose_actions.cpp` (window action only); `src/sys/compose/views/compose_view.h`; `src/ui/nuklear/compose/compose_layers_panel.cpp`; `src/ui/nuklear/compose/compose_state.h`; `tests/ui/` (one event-harness case); this card.
- **Steps:** 1. Reuse the Sounds panel's filter field component and its text-entry ownership rules (text entry must block Compose shortcuts). 2. Because the list is a bounded window over the whole catalog, filter in core, not in the frontend: extend the window request with the filter text so first row, count and total are all in filtered coordinates. 3. Keep the scroll position, target reveal and the filter consistent when the target is filtered out. 4. Verify matching, empty result, filter plus add/delete/rename while active, and bounded cost at 100,000 layers.
- **Invariants:** The filter is ephemeral per chart and never edits the document or Undo history. It does not change the paint target, visibility, solo or lock state, even for hidden rows. Matching is case-insensitive and Unicode-safe (names may be CJK); filter text length is capped. Name matching never allocates per layer on each frame.
- **Reject/failure behavior:** Over-long filter text is truncated at the cap; a stale window request is ignored and the next frame reprojects. A filter that matches nothing shows an empty state, not the full list.
- **Verify:** Core projection cases (filtered window, total, clamping); event-harness cases for typing, clearing and shortcut isolation; a bounded 100,000-layer timing check; GATE; documentation checks.
- **Out of scope:** Filtering by color, locked or visible state, or by note count; regex or fuzzy matching; persisting the filter; the Compose note-menu layer submenu (it keeps its own window).

## T-789 Unlink layers below a minimum element count

- **Status:** ready (not started; recorded 2026-11-15)
- **Outcome:** A Layers panel action, "Clean up small layers...", asks for N and then removes (unlinks and deletes) every unlocked layer whose element count is below N, in one Undo step. A preview shows how many layers and elements it would affect before confirming.
- **Read first:** AGENTS.md; this card's shared facts; `semantic_layer_delete_options_t` and the Delete + unlink path in `src/sys/compose/actions/compose_actions.cpp`; `compose_semantic_layer_view_t::assigned_note_count` and `assigned_bgm_count`; `src/ui/nuklear/chrome/` dialog components.
- **Files owned:** `include/wormedit/core/semantic_layer_editor.h`; `src/core/semantic_layer_editor.cpp`; `tests/core/semantic_layer_editor_tests.cpp`; `src/ui/frontend/actions.h` (appended action kind, threshold payload); `src/sys/compose/actions/compose_actions.cpp` (bulk action only); `src/sys/compose/views/compose_view.h` (preview counts); `src/ui/frontend/compose.h`; `src/ui/nuklear/compose/compose_layers_panel.cpp`; `src/ui/nuklear/compose/compose_state.h`; `tests/ui/` (one event-harness case); this card.
- **Steps:** 1. Define "element" once. Recommended reading: notes plus BGM events assigned to the layer (`assigned_note_count + assigned_bgm_count`), so a layer holding only BGM events is not treated as empty; confirm with Zar. 2. Add one core bulk edit that selects the qualifying layers by the chart-wide count and applies remove-from-notes plus delete atomically, with a dry-run query for the preview. 3. Add the threshold entry using the shared chrome dialog/number field and show "N layers, M elements will be unlinked". 4. Verify against selection-independent behavior (the count comes from the whole catalog, not the visible window) and Undo.
- **Invariants:** Counts come from the whole catalog, never the scrolled window. Locked layers are skipped, not rejected, and the preview says how many were skipped. Notes of removed layers become unassigned ("No layer") and keep their sounds and every gameplay field; sound defaults that referenced a removed layer are cleared in the same step. The paint target moves to "No layer" if it is removed. One action is one Undo record; zero matches is a no-op with feedback and no Undo entry.
- **Reject/failure behavior:** N below 1 or above the configured cap, a stale revision, an active gesture, or an unconfirmed dialog does nothing. If any qualifying layer cannot be deleted for a non-lock reason the whole request rejects atomically.
- **Verify:** Core cases (threshold boundaries at N-1, N, N+1; locked skipped; BGM-only layer; sound-default clearing; Undo/Redo; 100,000-layer bound); event-harness cases for the dialog and preview; GATE; documentation checks.
- **Out of scope:** Deleting layers by other criteria; merging small layers into a neighbor; automatic cleanup on save or import; touching layers on other charts.
- **Open questions for Zar:** "Desligar" is read here as unlink the elements and delete the layer, matching "Delete + unlink". Should the layer instead stay in the list, empty, with only its memberships removed? Does "elements" mean notes only, or notes plus BGM events?
