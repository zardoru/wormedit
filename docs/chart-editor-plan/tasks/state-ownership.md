  - One format diagnostic, `format_diagnostic_t<Code, Location>` with shared severity/code/message; each format keeps only its code enum and location type (line/column, JSON path, byte offset). Parse and write outcomes become `attempt_t<song_document_t, …>` and `attempt_t<std::string, …>`.
  - `diagnosed_t<bool>` dispatch outcomes share one named type.
  - Audition and preview SDL outputs share one set of status/outcome types, instantiated twice where behavior is the same.
  - Status enums (owner 2026-10-14: "those status enums too"): one shared failure code (capacity, invalid request, stale generation, cancelled, decode failure, not started, …) carried by `error_t`; a domain status enum survives only for values it alone has and that a caller branches on, and lifecycle states (`ready`, `started`, `inactive`, `complete`) live in one place per owner, not beside its failures. Target: a small fraction of the 55 `*_status_t` and 19 `*_error_t` on 2026-10-14; the inventory records each survivor with its reason.
  - `result_t<X, X>` becomes the effect struct with a status (it is not success-or-error); aliases naming one return are spelled out in the signature.
  - Rule (into code-style.md): an outcome alias exists only when several signatures share it or it hides a hard-to-read type.
