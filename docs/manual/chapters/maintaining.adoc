= Maintaining this manual

This appendix is for people editing the manual.

* *Reference tables* in `docs/manual/generated/` come from the editor's code. Regenerate them
with `cmake --build build --target manual-reference`; the `documentation.manual_reference` test
fails when they are out of date.
* *Screenshots* are captured by `scripts/manual-captures.sh` in an isolated X server from the shot
scripts in `docs/manual/shots/`, using the projects in `docs/manual/fixtures/`. Each capture
records the commit it shows in `docs/manual/images/revisions.adoc` and in the PNG's comment;
captions print it. `scripts/manual-captures.sh --check-stale` lists shots whose interface code
has changed since they were taken.
* *Links, includes and images* are checked by the `documentation.manual_links` test.
* Build the book with `asciidoctor docs/manual/index.adoc`. The CMake build does this too (target
`manual`, part of the default build) and `cmake --install` puts the HTML in a `manual/` folder next
to the program, so packages such as `scripts/windows-cross-package.sh` include it. Opt out with
`-DWORMEDIT_INSTALL_MANUAL=OFF` (for the Windows script, `CMAKE_ARGS=-DWORMEDIT_INSTALL_MANUAL=OFF`).
Without Asciidoctor a build only warns, but installing fails until it is installed or the manual is
turned off.

The build also copies `docs/manual/fixtures/` to `manual/fixtures/` and installs it there, so the
walkthrough exercises work from an installed manual. Captures use temporary copies of fixture
directories, keeping project edits and recovery journals out of the source examples. The
sound-import shot requires Zenity and forces its X11 backend inside the isolated display.
Its file picker is disconnected from the desktop session bus so a portal cannot forward it to
the user's desktop. `cmake --install build --component Manual --prefix <directory>` installs
the book, images, exercise fixtures and Lua API reference for a packaging check.

== Lua API reference

`docs/lua-api/` contains LDoc schemas, a scripting overview and runnable examples.
`cmake --build build --target lua-api --parallel 2` builds the offline reference; the
`manual` target builds both books. Pinned LDoc, Penlight and LuaFileSystem are fetched
as build dependencies. A separate native Lua runner also works when cross-compiling;
no system Lua or LuaRocks installation is required. The reference ships in
`manual/lua-api/`, including local styles, examples and license notices.
`documentation.lua_api_links` checks local HTML links and assets;
Lua tests execute the example files through the real generator and SV backend.
See `docs/building.md` for offline dependency overrides.

== Reader trial

The automated checks do not replace a first-time reader. Give someone who has not used Wormedit
the installed book and its fixtures, without coaching them through the UI:

. Have them create a project, import or arm a sound, place taps and a hold, move a note and Undo.
. Ask them to change the snap, play from the cursor and follow both walkthrough exercises.
. Ask them to preview an export and explain which files would be written before exporting.
. Record their platform, the manual revision, each step where they hesitated and the words or
  screenshot that would have helped. Separate manual ambiguity from an editor defect.

T-432 remains open for this independent reader trial. A maintainer reproducing the steps or
running the event harness is useful verification, but must not be recorded as that trial.
