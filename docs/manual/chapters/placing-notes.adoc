[#placing-notes]
= Placing and editing notes

== The three tools

The three tool buttons in Compose's top toolbar, and kbd:[Alt+1] to kbd:[Alt+3], choose what the mouse does
on the canvas:

[cols="1,2,4",options="header"]
|===
|Tool |Keys |Mouse

|Select
|kbd:[Alt+1]
|Click a note to select it; drag a note to move it; drag across empty space to select an area.
kbd:[Shift] adds to the selection, kbd:[Ctrl] toggles. kbd:[Alt]-drag on an empty lane draws a
hold; kbd:[Alt]-drag on a note changes its length.

|Draw
|kbd:[Alt+2]
|Click or drag to place the armed note with the armed sound; right-drag erases. A label near the
top of the canvas names what you are drawing, for example `Draw · 01 keysound-c4.ogg · right-drag
erases`.

|Layer
|kbd:[Alt+3]
|Click or drag over notes to add them to the targeted layer; kbd:[Alt]-drag removes them (see
<<layers>>).
|===

[#lane-keys]
== Lane keys

Each lane has a key, shown on its header. With the *Draw* tool active and nothing selected, a lane
key places the armed note at the cursor; on an occupied cell it removes that note instead (a whole
hold is removed if the cursor is anywhere on it). With notes selected, the same key moves every
selected note to that lane and keeps them selected.

kbd:[Shift] + lane key moves only the _first_ selected note to that lane, then deselects it. Press
again for the next one. To spread a selected run across lanes, press kbd:[Shift] with the lane
keys in the order you want, one note at a time.

Lane keys never repeat when held, so holding one cannot fill a lane by accident.

[#holds]
== Holds

From the keyboard::
Press and keep holding a lane key, move the cursor with kbd:[Up], kbd:[Down] or the page keys,
then release. Moving later stretches the tail; moving earlier moves the head. Releasing where you
started places an ordinary note. Several lane keys can be held at once for chords of holds.

With the mouse::
kbd:[Alt]-drag on an empty lane, or arm the *Hold* kind and draw. A new hold removes the taps it
covers and merges with holds it touches, all in one Undo step.

[#lengthening]
=== Lengthening and shortening notes

With the Select tool, kbd:[Alt]-drag an existing note along its lane. A tap becomes a hold
reaching the point where you release; a hold's end follows the pointer, and dragging it back to
the head makes it a tap again. The preview shows the result before you release, and the change is
one Undo step.

When several notes are selected and you kbd:[Alt]-drag one of them, every selected note changes by
the same amount, keeping its own start. If any of them would end up with a negative length, or
would run into another note, nothing changes.

This is the quick fix for the keyboard loop: type taps in rhythm, then kbd:[Alt]-drag the ones that
should be held.

== Note kinds

The note-kind palette in the toolbar arms what new notes become (*Options › Show note-kind
palette* hides it). Shortcuts arm the special
kinds directly: kbd:[Alt+4] mine, kbd:[Alt+5] invisible, kbd:[Alt+6] lift, kbd:[Alt+7] fake,
kbd:[Alt+8] roll. Kinds the chart's format cannot store are disabled; an explicit unsupported
request is refused.

== Moving, copying and deleting

* *Move*: drag selected notes with the Select tool, or use lane keys and kbd:[Shift] + lane key as
above. The *Y-lock* button in the toolbar keeps dragged notes on their rows.
* *Copy and paste*: kbd:[Ctrl+C], kbd:[Ctrl+X], kbd:[Ctrl+V]. Paste shows a preview that follows
the pointer; click or press kbd:[Enter] to place it, kbd:[Escape] to cancel. Paste also accepts
notes copied in iBMSC or BMSE (see <<pasting-from-bms-editors>>).
* *Delete*: kbd:[Delete] or kbd:[Backspace] removes the selection, or with nothing selected, the
note on the active lane at the cursor.
* *Undo*: kbd:[Ctrl+Z]; *Redo*: kbd:[Ctrl+Shift+Z].
Selection changes use the same chronological Undo/Redo stream, but are editor-only: they do not
mark the project as modified. A mouse press keeps the current selection until release commits
the click or area selection. During a selection gesture, kbd:[Escape] cancels the gesture and
keeps the previous selection; with no gesture active, it clears the selection.

== Selecting

[cols="2,3",options="header"]
|===
|Keys |Selects

|kbd:[Ctrl+A]
|All notes. kbd:[Ctrl+Alt+A] selects every kind of object (notes, BGM, timing, BGA…).

|kbd:[Ctrl+Shift+E]
|All notes after the cursor. kbd:[Ctrl+Alt+E] does the same for every kind of object.

|kbd:[Ctrl+Shift+I]
|Inverts the note selection.

|kbd:[Ctrl+Shift+A]
|Every note in the chart with the same sound as the selection.

|kbd:[Ctrl+Shift] + click
|Every note with that note's sound in the visible part of the chart. kbd:[Ctrl+Alt] + click does
it for the whole chart.

|kbd:[Escape]
|Clears the selection, or cancels the gesture in progress, without changing the active tool.
|===

You can also select a range from the keyboard: see <<keyboard-ranges>>.

== Background (BGM) lanes

Sounds that play without a note to hit live in the BGM columns to the right of the playable lanes.
Set how many there are with *BGM columns* in the toolbar. kbd:[`] moves the selected notes into
BGM, keeping their timing and sounds; kbd:[Shift+`] moves just the next selected note. Draw on a
BGM column with the Draw tool to place a sound there directly.
On BMSON charts, moving a linked playable note to BGM returns it to its original source stem,
keeping its timing and slice point.

[#lua-note-generators]
== Lua note generators

The link:lua-api/index.html[packaged Lua API reference] documents all context fields, return
values, sandbox limits and complete examples. It works offline alongside this manual.

In a Lua-enabled build, expand *Lua note generator* in the Compose inspector. Choose a `.lua`
file inside the project and set its seed, JSON parameter values and optional imported MIDI
asset IDs. *Run* prepares a preview; it does not edit the chart. Generated notes appear as green
ghosts, with separate added, changed and removed counts for notes and layers.

A script returns keyed notes and layers. For example, on an empty chart:

[listing]
----
local measure = wormedit.measures[1].id
local lane = wormedit.lane_profile[1].lanes[1].id
return {
  layers = {{key = "generated", name = "Generated"}},
  notes = {{
    key = "first", measure = measure, row = 0, lane = lane,
    kind = "tap", layers = {"generated"}
  }}
}
----

Use stable keys across runs. Measure and lane IDs are decimal strings; rows are exact integers.
A hold uses `kind = "hold"`, `end_measure` and `end_row`. Optional layer colors use integer
`r`, `g`, `b`, `a` components from 0 to 255. Parameters are available in the immutable
`generator.parameters` table; an exact fraction can be entered as `{"num":1,"den":2}`.
The immutable `wormedit` snapshot exposes the selection, measures, timing, lane layouts, notes,
layers and declared MIDI inputs. Scripts cannot access files or mutate the document.

*Apply* commits the entire preview as one undoable edit. *Cancel* discards it. Collisions,
invalid holds and invalid layers reject the whole batch. Choose *Keep recipe* to save the
frozen source, seed, inputs, parameters and output ownership with the ordinary editable notes.
Saving or opening a project never executes a generator.

Select a saved recipe and choose *Regenerate* to preview its changes explicitly. Existing keys
retain their object IDs. If the source or a declared MIDI input changed, the editor shows a
warning before running Lua; *Run changed script* acknowledges the captured version. You can
instead choose *Run saved source snapshot*. A changed project or target invalidates the preview.
For scoped BMS charts, select the recipe's saved Chart owner before regenerating.

Manual edits to generated notes or layers are preserved: regeneration rejects replacing an
edited or deleted output. *Detach recipe* removes its ownership record while keeping the current
notes and layers. You can then continue editing those objects normally.

=== A project.lua entry point

For a pattern spread across several files, choose a file named `project.lua` in the same
Lua generator file picker. Start with:

[listing]
----
worm_project "My patterns"
include "patterns/intro.lua"
include "patterns/main.lua"
----

Each included file can return the same keyed notes/layers shown above, or return helper
functions/tables for another module to use. Includes run once in order and resolve relative
to the including file. Output keys must be unique across the combined modules. Run produces
one preview for the selected chart; Apply is one Undo step. Using loose note/layer proposals targets the selected chart. Difficulty declarations
below instead create owned charts. The entry point does not rename the native project.

Optional `audio {id="music", file="song.ogg"}`, `image` and `midi` declarations track named
files and hashes in `project.assets`. They do not import files: use the existing asset import
and MIDI-input controls. Files and includes must stay inside the project directory, including
through symlinks. See the link:lua-api/modules/project.html[project declaration reference]
and link:lua-api/topics/README.md.html[downloadable example sources and limits].

Live Run freezes the included files and declared asset hashes. If any dependency changed,
review and confirm the captured script before applying. Discovery runs bounded Lua to find
the graph, but never edits the project. *Run saved source snapshot* uses the stored bundle,
even when its original files are unavailable. Opening or saving a project never runs Lua;
a failed run leaves the materialized chart intact.


=== Generated difficulties from measures

Choose a `.chart.lua` file, or include one from `project.lua`. For example:

[listing]
----
difficulty "Easy"
stable_id "easy"
resolution(960)
columns(4)
measure {id="intro", note {key="first", row=0, lane=1}}
measure {id="outro", note {key="last", row=240, lane=4}}
bpm {at=at_measure("intro",0), value=150}
----

Each `difficulty` starts a new owned chart. The selected chart supplies the script's
context. Run shows difficulty names and measure/note/BGM/timing counts; Apply commits
all difficulties as one Undo step. Select them in Project and use the existing output
groups for export destinations. Do not mix difficulty declarations with loose note/layer
return values. The link:lua-api/modules/chart.html[chart API reference] and
link:lua-api/sources/easy.chart.lua[complete downloadable example] cover holds,
BGM, meters, offsets, stops, delays, warps, scroll and reusable measure sequences.

Rows are local integers (see <<chart-rows>>). At resolution 960, a standard measure
has 960 rows; `meter(6,8)` gives 720. `row = capacity` is invalid, including a hold
endpoint: use row 0 of the next measure. Timing declarations belong outside measures.
Use `ratio(3,4)`, `measure_length "0.75"` and `measure_time "-0.125"` for exact values.
Bare Lua numbers use bounded rational conversion; expand *Exact values* in the preview
to inspect the chosen fractions and error bounds, or copy the full report.

Keep difficulty `stable_id`, measure `id` and event `key` values stable across edits.
Regeneration retains native IDs. It owns chart names, grids, offsets, measures and their
notes/BGM, lane layouts/input, BPM, pauses, warps and scroll. Manual edits there cause
a conflict. Independent markers, SV recipes and metadata remain authored content:
removing their referenced measures rejects the whole batch, and resolution changes
are blocked while authored positions remain. Omitted difficulties are removed only
when no extra authored content remains. *Detach recipe* keeps the charts and releases
ownership. Saving or opening never executes scripts. Typed sample declarations remain
future work; optional numeric `sound` fields refer to existing sound resources.
