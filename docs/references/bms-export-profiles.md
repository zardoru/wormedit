- [`BMSDecoder.java`](https://github.com/exch-bms2/jbms-parser/blob/8108cd54a19275810e1f5d2c9586f008eb6db95e/src/bms/model/BMSDecoder.java) collects extended BPM/STOP/SCROLL declarations and accepts LNMODE (0–3) and PREVIEW. This is decoder evidence, not a complete player playback check.

The `beatoraja` writer profile is the default. Untouched legacy text is decoded and re-encoded with a UTF-8 BOM while retaining its lines and line endings; `convert_untouched_source_to_utf8=false` keeps the original bytes. Already-UTF-8/ASCII unchanged imports retain their bytes. Normalized output defaults to BOM-prefixed UTF-8. Existing explicit low-level `output_encoding` overrides remain available for callers that deliberately request a different encoding.

`lr2_compatible` is a conservative classic-command subset, not an assertion that every LR2 build accepts every extension ever used by LR2 charts. It defaults to CP932, rejects unrepresentable text, LNMODE, SCROLL/SC, PREVIEW, unknown headers and unsupported SWITCH-family control flow with classified diagnostics, and retains classic BPM/STOP and long-note channels. Matching untouched CP932/ASCII input remains byte-identical. Selecting the modern profile for a legacy import is an explicit profile conversion; disable untouched-source transcoding to preserve the original source encoding.

Player names in `conversion_request_t::target_profile` select the player policy; existing BMS lane-profile names retain their prior meaning. The typed `conversion_request_t::bms_profile` (CLI JSON `bms_profile`) selects a player independently when an explicit lane map is also needed. Conflicting explicit player choices reject the request. Lane mappings and output extensions still derive from the chart when selecting a player profile. Scrolls are imported and projected as core exact multipliers. Normalizing a retained branch program containing semantic scrolls requires explicit `flatten_active`; raw unchanged branch source can still round-trip. Broader scoped-program authoring remains in T-731–T-744.

The same directory retains `T282ExportProbe.java`, `t282-actual-decoder-final.log` and CLI requests/results under `cli/`. The pinned decoder reads actual writer outputs in UTF-8 and CP932 with the Japanese title and all eight playable notes intact, and a modern output with exact zero and −0.75 scroll multipliers. The probe inputs use a complete seven-key/scratch channel family so automatic input lane detection is unambiguous; choosing an output lane map does not resolve ambiguous raw input channels. This remains the existing T-112 input-profile limitation.
