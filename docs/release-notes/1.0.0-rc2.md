# Wormedit 1.0.0-rc2 release notes

The second release candidate of Wormedit 1.0, a rhythm chart editor for BMS, BMSON,
StepMania and osu!mania. It fixes what rc1 testers and the maintainer's own charting turned up,
makes crash recovery cheap enough for large charts, and reworks much of the interface. Please
keep trying it on real charts and report what breaks before 1.0.0.

## Downloads and requirements

| Platform | Download | Requirements | Status |
| --- | --- | --- | --- |
| Windows | `wormedit-1.0.0-rc2-windows-x64.zip` | 64-bit Windows; a GPU with Direct3D 12 or Vulkan | Packaged and checked under Wine; please report results from real Windows machines |
| Linux | `wormedit-1.0.0-rc2-x86_64.AppImage` | x86_64, glibc 2.35 or newer (Ubuntu 22.04 era and later), X11 or Wayland, a working Vulkan driver | Packaged and checked |
| macOS | Build it yourself with `scripts/macos-package.sh` (see `docs/building.md`) | Apple Silicon or Intel, Xcode Command Line Tools, Homebrew | No download; rc1 was verified on Apple Silicon, rc2 not yet |

Unzip the Windows package anywhere and run `wormedit.exe`. Make the AppImage executable
(`chmod +x`) and run it. Both include the offline user manual (**Help → User manual**), the
Lua API reference, the manual's exercise files and the third-party license notices.

**macOS builds are not signed or notarized.** On first launch, right-click the app and choose
**Open**, or use **System Settings → Privacy & Security → Open Anyway**. A build made with
Homebrew's FFmpeg is for your own use only; it is not redistributable.

## Upgrading from rc1

- **Re-export osu!mania charts that use custom hitsound files.** rc1 quoted the `hitSample`
  field, which osu! reads as part of the first number. rc2 writes osu!'s own comma-separated
  form.
- rc2 writes **project schema 28** (rc1 wrote 25). rc1 projects are upgraded when opened; rc1
  refuses a project saved by rc2, so keep a copy if you may go back.
- Recovery journals now use a compact format. Journals left by rc1 are still read.
- Saved dock layouts gain the new **Mixer** and **Generator** panels at the end.

## What's new

- **Recovery that keeps up with big charts.** The journal records only what each edit changed,
  keyed by stable identity, with periodic full snapshots. Moving one note in a dense BMS chart
  went from a 24 MB record and about 1.4 s of background work to a few hundred bytes. Project
  saves are compact as well.
- **Mixer dock.** Music, BGM, Keysounds and Hitsounds buses under a Master level, each with
  level (decibel taper), mute and solo, applied live during playback. The mix is session state:
  it never changes the project or exports.
- **osu!mania hitsounds.** Optional volume, sample-set and addition-set columns beside the
  notes, and per-map sample overrides named like osu! skin samples (`soft-hitclap.wav`,
  `drum-hitnormal3.ogg`) that play in the editor and are copied beside the exported chart.
- **Interface.** Sections are rounded bars and cards; dock panels have filled headers; the
  Inspector is regrouped (Measure at cursor, Lane layout, Timing with Tempo, Audio offset and
  Timing event cards); the **BMS branches** panel is an icon tree with an action bar and
  collapsible node details; Project, Metadata and the recovery panel are laid out for wide
  screens. New desktop- and osu!-inspired color schemes; disabled controls are legible in light
  themes; text wraps between words.
- **Lua note generator** moved from the Inspector to its own **Generator** dock panel.
- **Open project folder** in the File menu and the command palette.

## Fixes

- **BMS:** flat (branch-free) BMS imports stay in one editable Chart, keeping comments, blank
  lines and unknown statements in place. Lane-key note moves and sound-layer membership work in
  prepared BMS charts, and edits to large BMS charts reuse unchanged projections instead of
  recomputing them.
- **BMSON:** opening errors name the chart file and the offending resource and JSON field.
- **Export cuts:** the shortened song is encoded as MP3 or Ogg Vorbis (chosen per export
  target); the uncut source music is no longer copied beside it; holds that cross a cut are kept,
  and omissions are reported per group. StepMania exports use standard four-beat bars on a
  bounded 192-row grid and report any rounding.
- **Export:** Export All and the replace/skip choices work from every tab, not only Compose.
- **Compose:** releasing a lane key over removed notes extends them into a hold; hold clearing
  and layered-hold merging; snap navigation after lane-key edits and after playback; paint
  ghosts in blank virtual measures; continuous lane decorations with fixed headers; the field is
  no longer squeezed by wide side panels; note-kind and hitsound palette buttons are no longer
  clipped.
- **Playback:** the player preview stays in sync across audio cuts; latched autoscroll keeps its
  speed.
- **Inspector:** SV-recipe graph axes stay put while scrolling; text fields keep focus while a
  tooltip is shown; light-theme Mixer contrast and selection highlights.
- **Recovery:** display-watchdog logs no longer show up as recovery candidates.

## Known limitations

Unchanged from rc1:

- **Audio Slices tab:** unfinished; expect its workflow and layout to change before 1.0.0.
- **Compare / Validate tab:** usable, but rough.
- **Storyboard tab:** disabled. osu! storyboards (`.osb`), the OSBX format and storyboard video
  export are planned, not shipped.
- **Formats not yet supported:** Quaver (`.qua`), StepMania rolls authoring and SSC
  `TICKCOUNTS`, and Standard MIDI import and export.
- **Sounds:** one sound per note. Layered multi-voice sounds and BMSON layered authoring are
  planned.
- **Interface language:** English only. Japanese, Chinese and Korean text in charts and file
  names displays correctly, but the interface is not translated.
- **Lane layouts:** Metadata's key-count selector lists **Custom** but it is disabled until a
  per-lane mapping editor exists. BMSON 48K charts have no per-stage focus for lane keys.
- **BMS repair:** malformed `#IF`/`#RANDOM`/`#SWITCH` blocks are preserved exactly on export,
  but Wormedit does not yet offer repair suggestions for them.
- **Diagnostics:** import warnings and export losses are listed in notifications, but cannot
  jump to the affected note yet.
- **Icon:** the application icon is a placeholder.

## Reporting problems

Open an issue at <https://github.com/zardoru/wormedit/issues>. Include your operating system,
GPU and driver version, the exact error text, and, if you can, the project or chart that shows
the problem. The manual's troubleshooting chapter lists the messages Wormedit reports and what
to check first.
