## Current code constraints

The Compose pane now draws bounded scalar projections of the renderer-neutral field scene in Nuklear: layout bands, lanes, exact grid lines, notes/holds, comparison differences, selection styling, cursor geometry, audio-time bookmark/section projections, and live note-paint/rectangle/Space-range previews. Its retained frontend state wires core pointer/keyboard note editing, bounded atomic note-paint drags, rectangle selection, tap-anchor/tap-tail and press-hold/navigate/release Space selection, including blinking exact anchor and tail rows, selection-aware hold resizing, deletion, lane-key holds, vertical wheel scrolling, pointer-anchored wheel zoom, toolbar zoom, page scrolling, and reset actions. Revision-bound valid hold and duration-resize proposals render as noninteractive amber ghosts with subdued committed origins; generic move and invalid/destructive proposal geometry, select-and-drag move/property wiring, horizontal BGM routing, and several richer interaction modes remain unwired. Bookmark/section widgets with their revision-local draft state and the player-preview validator/compositor are separate frontend-private units. Metadata's large editable text/tag/format buffers form one frontend-private state aggregate in their own translation unit; Timing's staged numeric text, exact meter, SV-recipe form/gesture, and marker-drag state follow the same pattern. Audio/Slices likewise owns its revision- and asset-stamped sample-frame offset drag plus pending cancellation. Compose groups bounded keyboard/wheel queues, pointer and keyboard captures, navigation, area/move gesture anchors, chart/revision stamps, and note-label/semantic-layer editor buffers in a fourth tested private state unit. All four reset on initialization and shutdown so no retained pane state leaks across frontend lifetimes. Audio/Slices view validation, asset selection, waveform drawing, and exact offset-drag action composition now live in a reusable frontend-private panel unit shared by Metadata and the dedicated Audio tab; it accepts only a Nuklear context, scalar focus flag, backend-neutral view, and typed action. Metadata, Timing, and Compose composition remain in the shell, and the shared Timing/Compose double-click queue deliberately stays shell-owned. Audio-time navigation crosses the marker unit only as typed previous/next actions and scalar availability; exact marker lookup, timing projection, and preview-clock seeking stay in the application layer. Every extracted unit consumes the same backend-neutral C view/action boundary that remains reusable by a future frontend adapter.

The player-like preview is a separate backend-neutral scene rather than Nuklear-owned chart logic. Its immutable chart/revision index precomputes note scroll extents and queries them through a max-end interval tree; each frame consumes only the shared sample-frame clock and emits capped lane, receptor, hold, and endpoint geometry. Preview-only exact timing/scroll options support negative count-in rows without weakening strict editor queries. A bounded cursor over the same immutable schedule resolves all five background/poor/layer/video/storyboard slots, including deterministic replacement and seek reconstruction, and the validated snapshot is carried by the headless scene through the scalar C view. The optional `wormedit::visual_decoder` target owns explicit path resolution, bounded static decode, a thread-safe byte/entry-bounded project/revision-aware LRU, and a newest-generation-only task coordinator; it owns neither schedule state nor GPU objects. The application requests the active static resources and retains immutable completion payloads so scalar RGBA pointers remain valid for frontend composition. The core owns deterministic stretch, contain, and centered whole-pixel cover geometry, with contain as the current scene default. `src/ui/nuklear/player_preview.cpp` owns scalar validation and widget composition, while the separate backend-private `player_preview_texture.cpp` owns the fixed 64-entry/256-MiB OpenGL texture LRU, applies the shared layout, performs deterministic static-layer draws, and tears textures down. Its bounded typed result distinguishes invalid images, allocation, out-of-memory, rejected upload, size mismatch, unsupported identifier, and layout failures; the widget reports the first resource and indicates additional failures without suppressing healthy layers. Decode/layout/schedule/document policy remains outside the adapter, so a future wxWidgets or SDL3 GPU implementation can own different textures over the same view. Video/storyboard decoders, docking persistence, the planned SDL3 GPU renderer, and the video encoder remain absent.

The earlier Compose constraint about horizontal BGM routing is resolved: BGM wheel/autoscroll routing, stable-ID tile selection, revision-bound click-audition intent, startup decoder binding, exact clip preparation, bounded generation-aware decode lookahead, headless session/timeline ownership, and SDL device/callback/stream-flush output are wired. The enabled `transport.stop` command now hard-stops an active click preview and clears queued device samples. Recovery/session replacement reconciles the project-scoped audio-asset inventory, hard-stops playback before removing stale decoders, assigns fresh immutable binding identities, and reports assets that cannot be reopened. Property editing, pane-specific drag geometry, and smooth trackpad gesture lifecycle remain unwired.

- `src/common/chart.cpp` imports through `libotoworm` and converts most event positions to seconds.
- `src/common/Chart.h` uses chart-wide time-keyed maps and a fixed `MAX_CHANNELS` constant.
- BMSON slice data, source sound channels, BGM events, measure lengths, and much source metadata are currently discarded by wormedit's conversion.
- `src/editor/field.cpp` has no implementation yet.
- `src/sys/audio.cpp` still only owns SDL audio subsystem lifetime; private one-shot and chart-preview adapters own their playback streams. The first Audio/Slices waveform overview is wired through the task scheduler and Nuklear draw boundary, while timing-aligned waveform navigation, slice markers, and SDL GPU rendering remain separate.
