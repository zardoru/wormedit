## Current milestone

The plan now makes the chart-play surface an explicit modeless live preview inspired by DDReam, osu!mania, and StepMania. It remains visible as a dock, detachable panel, or bounded picture-in-picture overlay while ordinary editing continues, shares the one transport and immutable preview schedule, and initially simulates presentation only—no judgement, score, life, failure, or gameplay-input rules. A very late Stage 7 consumer adds **Export player-preview video** to the area-selection context menu, rendering the exact selected interval through the same deterministic sample-frame scene/audio path with cancellable temporary output and atomic publication.

The first player-like preview slice is implemented as a modeless movable/scalable overlay over a deterministic headless scene and the shared transport. Static layers render through SDL3's GPU-backed renderer, while the bounded headless storyboard-frame evaluator now feeds decoded sprite instances through the player scene and scalar frontend boundary at the same transport time. The preview's caches, arenas, decode payload, and borrowed view storage live in a dedicated frontend-neutral application presenter rather than the application shell. Sprite rotation/flip rendering, concrete video evaluation, docking/detaching polish, and the very-late selected-area video exporter remain future work. Detailed implementation state lives in the [visual-preview ledger](implemented/visual-preview.md).

Timing BPM staging is now decimal-first without making binary floating point authoritative. Positive integer, decimal, and fraction text parses directly to exact rationals; terminating values display exactly, while non-terminating values show a clearly labeled decimal approximation beside their retained lossless fraction. An opt-in advanced fraction editor remains available, and frontend/app synchronization distinguishes authored decimal edits from display-only approximations so confirming an unrelated change cannot quantize `7/3` to its displayed decimal. Adjacent `-1`/`+1` steppers operate on that authoritative rational rather than the approximation, retaining denominators and rejecting zero/negative or overflowing results before the staged preview changes. The Nuklear frontend's behavior-preserving pane split is complete: Compose, Metadata, Timing, Audio/Slices, and player-preview validation/composition now live outside the SDL/Nuklear lifecycle shell, while each pane's retained editing state is grouped in a separate frontend-private unit with explicit reset. Compose owns scalar event queues, validation, frame preparation, action composition, and rendering; the shell only normalizes SDL events and retains the bounded double-click batch shared with Timing. These cuts retain the current C view/action boundary and leave a possible wxWidgets adapter outside current completion criteria.

The plan and status handoff now use small stable indexes backed by nested domain slices. The active milestone and resume checklist no longer carry the historical implementation ledger; editing/frontend planning is split into layout, interaction, and interoperability slices, player-like presentation/video has its own playback slice, and visual-preview implementation state has its own ledger. Existing entry-point links remain valid, and a CTest documentation gate verifies the complete index inventory, one H1 per file, and every local Markdown link. The current native test count is recorded after each full verification rather than inferred here.

Detailed completed work is indexed separately in the [implemented-capability ledger](implemented.md).

Compose's semantic-layer palette now surfaces revision-cached per-layer note membership counts. Deleting an unused layer remains the narrow ordinary action; a populated layer instead exposes a distinct **Delete + unlink** action that opts into the core's bounded atomic membership cleanup, remains undoable, and avoids silently broadening Delete. The application captures the stable layer ID before publishing the document command, removing a stale-pointer hazard in the post-delete filter cleanup path.

Semantic-layer colors are no longer limited to cycling six presets. An inline RGBA picker retains its changes as a frontend-local draft, displays the exact quantized 8-bit components, and offers Apply/Cancel; only Apply crosses the backend-neutral action boundary and creates one undoable exact-color command, so continuous picker motion does not pollute document history.

The semantic-layer palette keeps nine bounded frontend slots while paging across every eligible layer through a pure core projection. Previous/Next navigation and its page number are application-only state, local shortcuts 1–9 select the currently displayed window, and normal browsing does not mutate the document or abandon an off-page target. A selected hidden or newly selected off-page stable ID is revealed automatically; visibility or deletion changes clamp the requested page. Core coverage verifies stable chart indices, hidden-selection inclusion, clamping, and capacity rejection.

The Timing pane now exposes the first visual SV-recipe workflow. **New SV recipe** arms a vertical range drag over the Scroll/SV lane; the application converts normalized pointer bounds to exact chart positions, snaps both ends to the timing grid, and opens a revision-bound transient draft. Constant, linear, exponential, and finite bump parameters, generic SV/StepMania `SCROLLS`/`SPEEDS` output, fixed point-count/row-step or adaptive sampling, and SPEEDS transition settings can be edited as exact values. Dragging near either selected boundary resnaps that endpoint, while dragging the interval body translates the span. Amber raw-candidate and mint authored-baseline-times-composed curves are projected through bounded 4,096-point frontend arrays, with large batches decimated by row buckets while retaining boundaries and local extrema. Preview compilation runs only when the draft changes, never per render frame; Apply publishes one insert/update command and Cancel, timing lock, tab/chart/revision changes, or capture loss discard the draft without mutation. The core draft API also supports replacing an existing recipe in its stable composition slot; visible handles plus recipe-list selection/reorder/enable/duplicate controls remain later UI work.

The Compose pane now exposes an explicitly armed note-placement Paint tool. Pointer capture interpolates snapped cells through the existing bounded controller, shows additions in green, tap removals in coral, and non-tap or overlap collisions in amber, then commits a valid stroke as one atomic command. Revision, focus, mode, capacity, modifier, or shortcut preemption cancels without mutation. Hitsound/keysound assignment painting remains a separate future tool; semantic-layer painting and select-and-drag movement are now available through their dedicated tools.

Hold entry now keeps its pressed row as a fixed anchor and supports a moving head in either direction for Alt/Option drags and held lane keys. At release, it atomically removes covered plain taps and unions touching or overlapping plain holds on the active lane; special or metadata-bearing notes reject without mutation, and an occupied plain lane-key target removes the whole object. The Compose field renders the normalized reverse head/body/tail ghost, while a ghost showing the full forthcoming merge/removal set remains future work.

Compose also exposes a bounded note-label toolbar for the current explicit note selection. Apply sends its revision-bound UTF-8 field—including an intentional empty label—through the existing atomic label command; Clear sends the distinct null label request. The controls are unavailable without a selected note or usable field scene, and command diagnostics/no-ops return through the normal workspace status path.

Visible semantic-layer membership now tints Compose note endpoints and hold bodies through the renderer-neutral field scene. The first visible matching layer in the chart's ordered palette supplies the deterministic compact color when a note has multiple memberships; hidden layers are skipped. Selection, hover, paint, and proposal cues continue to take precedence as overlays, while valid move/duration proposal ghosts retain their source layer color. Compose exposes the first compact visible-palette toolbar: each of its bounded nine slots shows its stable layer ID, can create a uniquely named layer with a deterministic palette color, arm that layer, rename or recolor it, safely delete an unused layer, reorder it with Up/Down, show/hide it, select every matching note, and provides revision-bound Add/Toggle/Remove controls for the selected notes. A hidden selected target remains accessible only to restore it, while hidden layers stay out of the numbered shortcut palette. Its separate Layer Paint mode requires an unlocked visible target, captures an unmodified pointer stroke across existing notes, ignores empty travel between them, deduplicates revisits, and commits the full membership toggle as one undoable edit; target/mode/focus/revision/capture loss cancels safely. The same palette target now has a view-only Solo switch and selected-layer Require/Exclude filter toggles with active-state feedback. Those filters are ephemeral and chart-scoped, are cleared when the selected difficulty changes, and are removed automatically if their layer is deleted. The renderer-neutral scene accepts conjunctive required and excluded stable-ID sets, rejects unknown, duplicate, or contradictory filters, and retains only matching notes without changing the document. Lock/Unlock preserves the layer name/color/visibility; locked targets and active gestures cannot mutate membership. Richer multi-layer visualization remains later work.
