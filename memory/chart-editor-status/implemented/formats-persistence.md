# Implemented: formats and persistence

[Back to the implemented-capability index](../implemented.md).

The shared conversion request now drives a bounded detached preparation service for native projects, BMS-family files, SM/SSC, osu!mania, and BMSON. It applies optional exact quantization to a copy, requires explicit BMS branch flattening and typed StepMania policies where applicable, maps target diagnostics into one loss-aware result, deterministically groups SM/SSC or emits per-chart artifacts, enforces output count/byte/name limits, and re-import-validates every artifact before returning the atomic set. It accepts either one selected chart or an ordered chart subset; the subset restricts grouped SM/SSC output to the selected difficulties. It neither mutates the source document nor publishes files, so the UI preview, CLI, and filesystem publisher can consume the same result.

The conversion request can now carry bounded export-directory-relative paths for assets already staged by the file-copy service. It rejects unknown or duplicate asset IDs, duplicate destinations, rooted/traversing/control-character paths, and targets whose writer cannot yet consume this mapping. BMS, BMSON, and osu!mania receive path changes only in the detached document; BMS bypasses unchanged-source-byte emission so staged WAV/BMP declarations reach the output. The copy service returns the `assets/...` chart-relative reference from its project-relative publication path. A read-only publication planner resolves a validated conversion set against one selected output group, checks chart membership, overwrite policy, staged-asset existence, collisions, and symlink components, and returns no partial plan on failure. The headless publisher replans, copies a bounded existing output directory into a sibling temporary, writes and verifies all chart bytes there, and swaps the entire directory on Linux/macOS (or atomically creates a new directory where supported). Pre-publication failures preserve the prior directory; cleanup and parent-sync failures after publication are warnings. Compose now offers Export selected group with an explicit replace-existing-chart-files control for loaded native projects. A background task converts the selected group's ordered charts, applies asset mappings recorded by successful export copies in this session, and publishes the group; completion status surfaces conversion/publication errors. The UI currently rejects lossy conversions and does not expose full target-profile/branch-policy controls. The publisher requires an existing parent and a non-root group directory, rejects symlinks in the existing tree, and does not yet prune old generated filenames. Tests cover multi-chart replacement, chart-subset selection, and injected faults. StepMania asset-path substitution, persistent staged-copy manifest, Windows existing-directory exchange, root-level chart paths, and stale generated-file pruning remain.

Latest evidence update: the osu!mania v128 fixture covers the ordered General, Editor, Metadata, and Difficulty inventory observed in the pinned official lazer encoder, including `VelocityPresets`, and export/re-import preserves it. This is positive encoder evidence only: Wormedit does not infer that fields absent from the stable wiki are forbidden in v14. Broader implementation-specific behavior remains outside the advertised profile.

Latest StepMania evidence update: file family, warp syntax, and named application/release targets are separate policies. Pinned `stepmania_5_1` and `etterna_0_75_1` profiles accept and emit only the fixture-backed SSC 0.83/native-`WARPS` subset; they reject `.sm`, legacy syntax selections, and negative-BPM/negative-STOP warp input rather than implying unverified compatibility. Syntax-only native and legacy conversion policies remain available without a player claim. A typed `stepmania_export_policy_t` now travels in the shared conversion request and resolves those three explicit selections into writer options with typed compatibility errors; document-specific losses remain the writer's transactional responsibility.

The wormedit-owned BMS byte reader detects ASCII/BOM UTF-8, uses explicit overrides for ambiguous legacy encodings, preserves shared original bytes and per-line encoded spans/endings, retains raw statements, and constructs RANDOM/IF/SWITCH control trees. At root scope it materializes TITLE/ARTIST, retains extended and syntactically safe custom metadata in source order, imports WAV/BMP resources, exact measure lengths, repeated BGM source lanes with structural `00` slots, direct and extended BPM, STOP, visible/invisible/mine notes, and background/poor/layer BGA channels when the caller selects a compatible lane profile. Missing BMP references become deduplicated relinkable placeholders while undefined WAV events remain unbound. Exact channel subdivisions promote chart resolution within a configurable cap; unresolved references remain diagnosed. Compatible selected profiles now pair long-note endpoints across repeated lines and measures, while odd or cap-incompatible endpoints remain raw with diagnostics. Explicit caller choices and fixed `SETRANDOM`/`SETSWITCH` values project branch-local metadata, definitions, measure ratios, and object payloads in source order without discarding alternatives; SWITCH fallthrough continues until `SKIP` or the block end. A bounded frontend-neutral branch evaluator owns that RANDOM/IF/SWITCH/fallthrough projection for the writer and returns immutable before/after previews with exact entering/leaving statement IDs and source orders. Invalid, duplicate, unreachable, stale-ID, depth/node-cap, and active-statement-cap proposals publish no usable delta. A separate frontend-neutral rematerializer now serializes the current representable semantics into the preserved complete tree, verifies that normalized output retained the exact nested control/raw-branch shape, maps choices independently of regenerated IDs/source orders, reparses the proposed projection, retains song/chart identity, chart metadata/meter/layout preferences, output groups, and runtime asset metadata, and publishes it through one revision-checked undoable command. Edited active branch payloads therefore survive switching away and back. Writer, parser, projection, structure, resource, and unsupported-editor-state failures reject without partial mutation; bookmarks, note labels/semantic layers, SV recipes, MIDI/generator state, and non-BMS metadata remain explicitly blocked until they can be mapped without loss. The bounded BMS writer preserves unchanged imported bytes exactly and otherwise emits deterministic UTF-8 BOM output for ordered metadata/custom fields, resources, exact terminating-decimal measure ratios, one initial BPM, taps and holds, repeated BGM lanes with structural `00` slots, and representable background/poor/layer BGA events. Explicit normalized output selection supports strict ASCII, UTF-8 with BOM, CP932, EUC-KR, CP949, and Windows-1252; unavailable codecs and unrepresentable text reject with typed diagnostics. Normalized saves default to emitting the complete retained RANDOM/IF/SWITCH program—all branches and corresponding control statements—without duplicating the selected materialized projection. Provenance-validated active-branch edits patch uniquely attributable metadata, WAV/BMP paths, measure ratios, notes and holds, BGM/BGA slots, direct and extended BPM events/declarations, and STOP pauses in place; other branches and control statements remain byte-stable, including unchanged delimiter whitespace. Per-field, measure-length, BPM, and pause source identities preserve exact root/branch ratios and mixed root/branch BPM/STOP definitions and channel statements; cross-measure moves, occupied-slot collisions, shared timing declarations, and structural or ambiguous changes reject. Safe root content edits remain supported. Inactive raw branch statements can be replaced, inserted after a source-verified anchor, or deleted through exact-provenance edits in an exact inactive leaf; deletion removes the retained line and compacts later spans/orders while preserving the complete control tree, including a valid empty leaf. Active, structural, stale, ambiguous, malformed, and oversized edits reject without mutation. Inactive insertion and deletion currently require exactly one chart in the BMS source document. An explicit resolved active-projection policy flattens currently materialized notes/resources/metadata into a control-free BMS with a loss warning and now emits projected multi-BPM timing through extended-BPM declarations/channel 08 and BMS-tick pauses through STOP declarations/channel 09. Values without exact terminating-decimal spellings reject rather than silently approximate. Ambiguous root/tree interleaving and timing/event classes without import projections remain source-backed. Semantic layers flatten to their gameplay notes and bookmarks are omitted with explicit warnings.

Conservative automatic lane-profile detection now treats a duplicate-insensitive complete visible, invisible, long-note, or mine channel family as evidence that a standard profile is exact rather than merely a compatible superset. Parser-backed fixtures select dense standard BME 7K/14K and PMS 5/9-button maps using that evidence together with extension and `#PLAYER`; sparse maps, raw-identical free-zone/foot-pedal semantics, BME 7K-foot-pedal versus BME-style PMS 9-button, and unnamed special double-scratch/Project2DX dialects remain ambiguous and unmaterialized. Special profiles require named header evidence such as `#OCT/FP` or an explicit choice.

The bounded paired osu!mania codec accepts and emits every key count from 1K through 18K using dynamic lane layouts, with every lane at every key count covered by semantic writer/re-import tests. A combined range test also preserves hit times, lane identity, and rewired measure lengths and boundary positions for all 18 counts; the generic project model remains uncapped by this format-specific limit. The reader retains bounded UTF-8 source metadata/bytes, absolute hit-object milliseconds, sample/resource data, tags, audio-time bookmarks, kiai/effect bits, backgrounds/video assets, holds, and inherited SV. Standard General, Editor, Metadata, Difficulty, and Colours fields now have read/write round-trip coverage, and metadata materialization has independent caller-configurable field-count and byte caps. Source-ordered uninherited timing points rebuild half-open editor measures with directional near-coincident line suppression and omitted-first-barline behavior; piecewise tempo integration keeps measure lengths and rows correct when an omitted reset changes BPM inside a displayed measure. The reader requires a numeric leading format header and now accepts two independently named profiles: stable v14 retains its integer hit-object timestamps, while lazer v128 accepts finite decimal tap/hold times and retains their exact source spellings. Other versions reject transactionally. The deterministic writer infers a supported imported profile unless explicitly overridden: stable v14 rounds notes and holds to nearest integer milliseconds with half ties away from zero, whereas lazer v128 emits finite decimal note and event times and preserves unchanged imported spellings. Explicit v128-to-v14 conversion surfaces timestamp quantization. Both profiles emit Mode 3/CircleSize, metadata/tags/bookmarks, BPM/meter/SV/kiai timing, samples, BGM, backgrounds, video events, and representable embedded Sprite/loop storyboard content while preserving safe retained format fields. Semantic layers decay to their gameplay notes with a warning; unsupported mines/invisibles/lifts/fakes, pauses/warps/speed curves, sustained BGM, branches, ambiguous multi-chart storyboard ownership, and structurally unmodeled trigger blocks reject explicitly. Broader version-specific metadata fixtures remain before the codec is advertised as version-complete.

A bounded paired SM/SSC codec now parses and writes ordered song/chart metadata, multiple difficulties, common 3/4/5/6/7/8/10-column step types, exact note grids, taps/holds/rolls/mines/lifts/fakes, signed OFFSET semantics, BPM, stops, delays, native and legacy warps, scrolls, and transitioning speeds. Imported format-only metadata stays in ordered format groups and safe unknown fields are re-emitted; unsafe delimiters and unfaithful note kinds reject rather than inject or silently become taps. SSC retains shared timing at song scope and chart overrides at chart scope; `CHARTNAME` and per-chart `CREDIT` map to editable chart metadata. SM global `CREDIT` maps to chart authors and export rejects conflicting per-chart authors instead of silently selecting one. The SSC reader is explicitly bounded to the audited StepMania 5.1 v0.83 semantics: omitted `VERSION` uses the upstream 0.83 default, explicit 0.83 is accepted, and duplicate, malformed, older, or future declarations reject transactionally before version-sensitive warp, split-timing, or chart-name rules can be misread. The SSC writer always emits one canonical `#VERSION:0.83`; `.sm` remains independent of that gate. The codec exposes explicit `native_warps`, `legacy_negative_bpm`, and `legacy_negative_stop` source/target syntax profiles; selecting one asserts the syntax family, so native and mismatched legacy encodings reject with a profile-mismatch diagnostic. These names do not claim compatibility with a specific player release. The `.sm` writer rejects native WARPS and nonempty SCROLLS/SPEEDS because standard SM consumers do not load them, while explicit representable legacy warp strategies remain available. Labels/layers decay to the underlying gameplay note with loss diagnostics and bookmarks are omitted with diagnostics. The v0.83 SSC fixture covers subtitle/transliteration, origin, song/chart credit, visual assets, preview/sample fields, display BPM, chart style, and chart music while retaining format-only fields. Broader implementation-profile fixtures and player/version compatibility evidence remain.

A standalone storyboard foundation provides a checked reusable chunked frame arena, a bounded source-ordered event schedule with binary seek and head-only realtime advancement, structural zero/large/nested OSB loops evaluated without expansion, all standard easing IDs, valid command-shorthand canonicalization, deterministic Sprite/transform/loop emission and semantic reparse, and retained unsupported directives. Structured models now persist in native `storyboard_document_t`; the version-1 JSON reader remains compatible with older raw-line storyboard entries, validates bounded OSB structure, and keeps unknown JSON fields rejected. Native write/read/write and OSB semantic re-import tests cover nested loops and retained lines. The osu!mania adapter imports and emits bounded difficulty-specific Sprite blocks, nested loops, and retained unknown lines beside ordinary BGM/background/video events, with semantic re-import validation. Animation headers and standalone parameter/sample directives remain opaque; trigger hierarchy, concrete drawing, and offline video rendering remain.

The wormedit-owned BMSON 1.0 reader and writer use pinned nlohmann/json 3.12.0. The reader validates bounded UTF-8 JSON and imports exact resolution, canonical and generic 24K/48K layouts, variable bar-line geometry, timing, metadata resources, playable notes/holds, non-playable sound-channel slices, BGM semantics, continuation/restart conflicts, and BGA events while retaining original bytes and field spelling. The writer selects one chart explicitly, represents positions and decimal timing exactly, preserves safe resource spelling and unknown source fields by provenance, treats retained sound-channel events as authoritative, and verifies semantic export/re-import. Same-path sound channels share assets but keep distinct resources. Semantic note layers decay to their underlying gameplay notes and bookmarks are omitted when exporting BMSON, both with nonfatal loss diagnostics. Resource paths accept and normalize either separator while rejecting rooted, parent-traversal, and NUL-bearing paths.

The first native-project codec uses a deterministic versioned nlohmann/json envelope and serializes the complete editable song aggregate: ordered charts and output groups, metadata/provenance, semantic layers and labels, bookmarks/sections, resources and asset paths, audio slices, MIDI bytes, generator recipes, storyboards, and retained BMS source bytes/control trees. Read and write enforce configurable byte, JSON-node, and nesting bounds; parsing performs a SAX limit pass before DOM allocation, requires exact schema/integer shapes, validates enum domains and the complete graph, and publishes no partial document on failure. Primary saves and checksummed recovery envelopes publish through exclusive same-directory temporaries, flush/re-open validation, exact ID/revision checks, atomic replacement, and directory durability sync where supported. The app now schedules dirty revisions on the monotonic five-minute cadence: saved projects use adjacent backups, while untitled/import sessions use their stable project ID in SDL's per-user recovery directory. One immutable snapshot at a time is submitted to a bounded worker; failures retain the primary and last good backup, surface status diagnostics, and back off before retrying. Bounded parsing and fault seams verify publication safety. The bounded startup scanner validates the primary, adjacent backup, caller-supplied recovery entries/directories, and interrupted primary/recovery temporary generations, compares project ID/revision before timestamps, and attaches content tickets. Startup resolves/creates SDL's per-user `recovery` directory and scans it. The headless executor revalidates tickets, returns guarded read-only/session documents, publishes create-only save-as files, and performs explicit discard/quarantine as verified same-directory recoverable moves with rollback; it never overwrites the primary implicitly. The bounded recovery banner exposes clipped rows, diagnostics, and explicit Inspect/Recover/Save-as/Discard/Quarantine actions with generation-bound tokens. Recover revalidates project ID/revision and waits for an in-flight autosave before replacing the session, then resumes from the recovered artifact's sequence and explicit-save baseline. With no primary or recovery directory, scanning reports unavailable. Filesystem packaging, command journals, crash markers, schema migrations, and inherited multi-difficulty metadata remain later slices.
