# Implemented: foundation and document core

[Back to the implemented-capability index](../implemented.md).

The planning review is complete enough to begin implementation. Stage 0 is establishing the build/test/dependency environment, fixture inventory, and loss-aware document foundation.

The Catch2 v3/CMake/CTest harness and pinned optional Lua 5.4.8 target are established. Thirty-one text fixtures cover BMS/BME/BML/PMS, SM/SSC, osu!mania, and BMSON positive and negative semantics, including the BMSON specification's published `vox.wav` slicing sequence transcribed to JSON, all zero/null/omitted default-resolution spellings, repeated StepMania legacy negative-BPM regions, and a focused StepMania 5.1 same-row discontinuity case. Eight byte-authored BMS streams now cover UTF-8 with BOM, CP932, EUC-KR, CP949-only text, Windows-1252, ambiguous ASCII, malformed UTF-8, and a truncated CP932 lead byte; authoritative lowercase-hex recipes are checked against every fixture byte-for-byte. Twelve generated MP3/Ogg assets provide short keysounds, a polyphonic chord, silence, and a bounded seek/stream source. [`tests/fixtures/README.md`](../../../tests/fixtures/README.md) is the capability inventory, and [`docs/fixtures/libotoworm-capability-audit.md`](../../../docs/fixtures/libotoworm-capability-audit.md) records precisely what the current library bridge exposes and discards. A pinned BMSE 3.0/iBMSC 3.5.5.16 source audit establishes that their clipboard formats are versioned and directionally compatible; runtime clipboard captures remain outstanding before Stage 0 reaches its exit condition.

The first replacement document slice is implemented in `include/wormedit/core/document.h` and `src/core/document.cpp`. It defines strong stable IDs, exact measure-local positions, ordered measure chunks, explicit notes/holds and BGM source lanes, typed timing/pause/warp/scroll/speed/kiai data, lane layouts and physical-key input profiles, semantic layers, resource/audio/visual/slice provenance, BMS control-tree storage, MIDI/generator/storyboard extension records, conversion requests/reports, and graph validation diagnostics. Validation now covers BMS control-tree shape, IDs, source spans/order, closing directives, active branch selections, namespaced case-insensitive BMS resource identities, and audio-only sound-channel sources. Exact measure-prefix indexing and atomic exact-only global redivision are implemented and tested; inexact positions reject without mutating the source chart.

Data-defined profiles now cover BMS 5K/10K free-zone and foot-pedal variants, BME 7K/14K with selectable inside/outside scratches and optional pedals, standard PMS 5K/9K, BME-style PMS 9K/18K, double-scratch/FPP, octave/foot-pedal, Project2DX, and BMSON-only generic 24K/48K piano banks. Each BMS-family lane keeps its exact visible/invisible/long-note/mine channel identities independently from stage, display order, role, and physical input binding. Confidence-ranked BMS profile detection now considers extension, `#PLAYER`, `#OCT/FP`, and used-channel evidence while retaining exact channel spelling/order in a custom fallback. Sparse, contradictory, unknown, or non-playable-only inputs do not invent a layout.

Stage-zero CMake now includes generic headless cross-toolchain presets for Linux targets and Windows/MinGW targets from Linux. Compiler paths, target triples, sysroots, resource compiler, and optional emulator/Wine paths are caller supplied; full application cross-presets wait for target-side SDL3 GPU/audio/package discovery.

The headless core also implements exact textual BMS measure-length parsing, bounded deterministic IEEE-754-to-rational conversion with explicit approximation/error reporting, exact row-capacity/meter validation, the default editor-to-BMSON grid mapping, and supported-snap filtering with a guaranteed one-row fallback. `quantize_chart_exact` provides standard-measure and authored-measure grids, deterministic ties, selection and hold policies, collision diagnostics, exact opt-in global-resolution promotion, cross-measure rehoming, movement previews, and atomic rejection for invalid holds/layout effects. A bounded whole-document command history publishes graph-validated edits atomically, provides undo/redo with monotonic revisions, tracks saved/dirty state, and exposes quantization through the same command boundary.
