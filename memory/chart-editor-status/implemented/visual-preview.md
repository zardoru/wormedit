# Implemented: player preview and visual evaluation

[Back to the implemented-capability index](../implemented.md).

The player-like preview is a modeless overlay that consumes a revision-cached headless scene at the shared transport sample frame. Its core index combines exact timing inversion, composed scroll/SV displacement, layout transitions, holds, split stages, semantic colors, reverse direction, and bounded interval-tree visibility queries. Neutral, mania, and arrow skins change presentation without adding judgement, score, life, failure, or gameplay-input rules. Preview-only pre-zero timing/scroll queries animate count-in notes without weakening ordinary editor queries.

The immutable preview schedule and bounded seekable cursor resolve source-ordered background, poor, layer, video, and storyboard activations. Static visual resources use a pinned optional `stb_image` decoder with checked project-relative resolution, byte/dimension/pixel limits, declared-geometry validation, a project/revision-aware CPU LRU, and newest-generation-only task publication. The Nuklear adapter owns a separate fixed-capacity `SDL_Texture` LRU over SDL3's GPU-backed renderer; decoding, layout, scheduling, and document policy remain headless and reusable by another frontend or offline renderer.

The storyboard model now has a separate renderer-neutral preview module. It builds an immutable, layer/source-ordered sprite lifetime index once per document revision and evaluates exact OSB milliseconds into bounded arena-backed draw instances containing asset path, origin, position, scale, rotation, opacity, and color. Mixed `M`/`MX`/`MY` and `S`/`V` commands resolve by evaluated start/source/visit order, nested loops remain structural, inactive sprites allocate nothing, and stale, ambiguous-ID, instance-cap, nesting, and arena failures publish no usable frame. The player scene now carries those instances at the shared transport time. A frontend-neutral application presenter owns the revision indices, per-storyboard arenas, visual cursor, decoded-image payloads, and borrowed scalar storage outside `main.cpp`; it resolves sprite paths through the existing resource catalog and image decoder. The Nuklear adapter draws the bounded sprites on the osu! 640x480 logical canvas with origin, scale, color, and opacity before chart geometry, while retaining rotation in the scalar contract for a renderer capable of applying it. Concrete sprite rotation/flipping, video decoding/evaluation, docking/detaching polish, and the selected-area video exporter remain outstanding.
