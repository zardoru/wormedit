# Implemented: player preview and visual evaluation

[Back to the implemented-capability index](../implemented.md).

The player-like preview is a modeless overlay that consumes a revision-cached headless scene at the shared transport sample frame. Its core index combines exact timing inversion, composed scroll/SV displacement, layout transitions, holds, split stages, semantic colors, reverse direction, and bounded interval-tree visibility queries. Neutral, mania, and arrow skins change presentation without adding judgement, score, life, failure, or gameplay-input rules. Preview-only pre-zero timing/scroll queries animate count-in notes without weakening ordinary editor queries.

The immutable preview schedule and bounded seekable cursor resolve source-ordered background, poor, layer, video, and storyboard activations. Active video events now evaluate to an exact reduced media timestamp from their activation frame and the shared sample-frame clock; replacement restarts at zero, while seek and repeated/offline evaluation are stateless and identical. The player scene and frontend-neutral scalar view carry this clock, and Nuklear exposes it even before a video decoder is installed. Static visual resources use a pinned optional `stb_image` decoder with checked project-relative resolution, byte/dimension/pixel limits, declared-geometry validation, a project/revision-aware CPU LRU, and newest-generation-only task publication. The Nuklear adapter owns a separate fixed-capacity `SDL_Texture` LRU over SDL3's GPU-backed renderer; decoding, layout, scheduling, and document policy remain headless and reusable by another frontend or offline renderer.

The storyboard model now has a separate renderer-neutral preview module. It builds an immutable, layer/source-ordered sprite lifetime index once per document revision and evaluates exact OSB milliseconds into bounded arena-backed draw instances containing asset path, origin, position, signed scale, rotation, opacity, and color. Mixed `M`/`MX`/`MY` and `S`/`V` commands resolve by evaluated start/source/visit order, nested loops remain structural, inactive sprites allocate nothing, and stale, ambiguous-ID, instance-cap, nesting, and arena failures publish no usable frame. The player scene now carries those instances at the shared transport time. A frontend-neutral application presenter owns the revision indices, per-storyboard arenas, visual cursor, decoded-image payloads, and borrowed scalar storage outside `main.cpp`; it resolves sprite paths through the existing resource catalog and image decoder. Renderer-neutral quad layout maps the osu! 640x480 logical canvas into any destination, rotates about the authored origin, and preserves negative-scale flips. The Nuklear adapter emits those quads through bounded custom draw commands, preserving clip and source order; Background/Fail/Pass sprites compose behind the chart field and Foreground sprites compose above it.

The optional `wormedit::video_decoder` target isolates FFmpeg demux, seek, decode, and RGBA conversion from core and frontend targets. It consumes the exact reduced player-preview media clock, selects the current frame without a floating-point timestamp, enforces dimension/pixel/byte/packet limits, and supports stop-token interruption. Its movable opaque session retains demux/codec state plus current/lookahead frames: monotonically advancing requests drain forward, backward requests seek and flush exactly, and the returned `[PTS, next PTS)` interval is open-ended only for the final frame. The job keeps one serialized session per project/revision/source behind its newest-generation cancellation boundary; the presenter does not enqueue another request while the delivered frame covers the live clock. The revision/time-keyed byte/entry-bounded CPU LRU still serves exact repeated requests. The scalar view assigns each delivered video generation an explicit content identity; Nuklear includes it in its bounded texture-LRU key, uploads changing frames, and continues drawing the prior frame while the next request is in flight. A three-frame lossless fixture covers exact decoder selection, forward reuse, backward seek, interval throttling, cache/job bounds, cancellation, presenter publication, and red-to-green-to-red replacement. Late-frame diagnostics, docking/detaching polish, and the selected-area video exporter remain outstanding.
