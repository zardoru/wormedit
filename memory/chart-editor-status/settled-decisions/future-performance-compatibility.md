# Settled decisions: deferred work, performance, and compatibility

[Back to the settled-decision index](../settled-decisions.md).

- Defer osu! storyboard authoring, OSBX/video export, and Lua generation until the core milestones are stable, while keeping model extension points and lossless source retention.
- Use a native, versioned project format that stores Lua generator recipes, declared asset inputs, parameters, deterministic seeds, hashes/provenance, and materialized editable notes.
- Import MIDI as a project asset and expose structured exact-tick MIDI data to Lua through a cross-platform host API. Loading an asset alone does not change chart timing, and regeneration remains explicit and previewable.
- Use a Premake-style, versioned OSBX Lua DSL. Storyboard and note modules can be separate; one project can emit several difficulties, including grouped SM/SSC output.
- Allow Lua generators to emit notes/layers, OSBX storyboard objects/keyframes, or both in one transaction.
- Use a keyframe-style OSB/OSBX editor and one deterministic scene evaluator for preview, OSB compatibility compilation, and offline video rendering.
- Back OSB/OSBX preview and offline rendering with a checked dynamically growing frame arena that recycles temporary draw/evaluation storage while durable nodes and stable IDs remain outside it. Compile event queues into bounded pre-sized sorted arrays, binary-search the head on seek, and advance a head handle without runtime node allocation. Preserve OSB loop blocks structurally, evaluate relative child timing without unbounded expansion, and support deterministic standalone/embedded `.osb` emission and semantic re-import.
- Compile playable, BGM/autoplay, BGA/visual, timing/metronome, and storyboard preview events into bounded sorted contiguous queues. Binary-search each family head on seek/loop and advance handles in realtime; retain simultaneous BGM polyphony/source order and BGA draw order without queue-node allocation.
- Let an exact area/Space-selected chart interval and explicit requested duration generate `preview.ogg` through the shared mixer, with previewable trim/loop/fade-out policy, bounded async progress/cancellation, deterministic encoding, stale-generation rejection, and atomic output publication that preserves any prior file on failure.
- Use each measure's contiguous note/event vectors as spatial buckets, narrowed by the exact measure-prefix index and optional invalidated derived span indexes. Benchmark at least 50,000 notes under even and dense-measure distributions for validation, selection/hit testing, schedule compilation/seek, draw composition, allocations, and peak memory. Target discrete interaction p95 latency at or below 125 ms; continuous selection, dragging, and scrolling have a 33.3 ms p95 ceiling, 16.7 ms target, and 8.3 ms aspirational 120 Hz tier on documented reference hardware, with calibrated performance-CI tolerances.
- Keep persisted documents platform-neutral, but build parallel load/index/schedule projections from deterministic measure ranges with platform-selected cache-line alignment, worker-local scratch/counters, no shared hot writes, and stable-order reduction. Stress false-sharing boundaries and dense-measure subdivision on each reference platform rather than persisting one machine's allocation geometry.
- Parallelize peak/RMS waveform pyramid construction above a calibrated workload threshold using disjoint channel/block output spans, worker-local accumulators, deterministic higher-level reduction, cancellation checks, and a serial fast path for short assets.
- Use a project-owned bounded continuation/task-graph interface for render preparation, analysis, parsing/indexing, and heavy exports. Start with a C++20 `std::jthread`/`stop_token` backend with worker-local queues, dependency counters, typed results, generation-checked UI publication, and bounded task/byte fan-out; keep the executor replaceable if profiling shows the standard-only backend cannot achieve Rayon-style parallelism consistently.
- Support storyboard-to-video export through an encoder interface; evaluate FFmpeg libraries and a packaged/discovered FFmpeg process across Windows, macOS, and Linux.
- Treat `libotoworm` only as readable reference code and fixture evidence. Wormedit owns every production parser, writer, timing evaluator, and converter; do not add or extend it as the implementation path.
- Detect BMS encoding from bytes with user override for uncertain cases. Support at least UTF-8, CP932/Shift-JIS, EUC-KR/CP949, and Windows-1252; normalize internally to UTF-8 and retain original bytes/encoding for loss-aware saves. Evaluate iconv-compatible conversion.
- Preserve ordered osu! search tags, millisecond bookmarks, labeled native song sections, and kiai timing state. Editing kiai must retain other timing-point effect bits.
- On osu!mania import, rebuild ordered editor measures from source-ordered uninherited timing points and their meter fields. Each effective point resets bar phase; inherited SV points do not. Keep absolute hit-object milliseconds canonical, use half-open boundary ownership, preserve timing displacement when a near-coincident bar line is hidden, and fixture the stable-client quirk rather than copying `libotoworm`'s approximate 1.2 ms implementation.
- Support editable custom BMS channel maps connecting semantic lanes to raw BMS channels and optional MIDI channel/note destinations.
- Ship data-defined command-memo BMS lane profiles: BMS 5K/10K, BME 7K/14K, standard and BME-style PMS 5K/9K/18K, plus named free-zone/foot-pedal, double-scratch, octave, and Project2DX variants. Historical MGQ remains raw/custom BMS data rather than a Keyboardmania profile. Keep semantic role, raw channel, display order, and input binding separate.
- Detect a BMS layout only with sufficient extension/header/channel evidence; ambiguous or unusual layouts remain lossless custom maps. Mirror semantic lanes across visible/invisible/LN/mine families only where the selected profile defines them.
- Store invisible notes, long notes, mines, and retained target-specific note kinds explicitly. BMS uses its parallel channel families, StepMania retains its native symbols, BMSON supports taps/long lengths, and unsupported exports require a diagnosed explicit transform.
- Preserve StepMania roll and tick-count provenance early, but defer full roll re-hit/life authoring and Pump-style ticked-hold timing/preview/export to the late compatibility milestone after the main formats are stable.
- Export Standard MIDI through those maps with explicit musical and audible-performance timing policies and no silent tick quantization.
- Preserve BMS `#RANDOM`/`#SETRANDOM`, IF/ELSEIF/ELSE, and SWITCH/CASE/DEF/SKIP structures as an ordered tree. The chart view renders root/common content plus the leaves activated by explicit manual or seeded branch choices. Direct branch-body and structural editing is desirable but lower priority than lossless preservation and projection controls.
- Branch edits eventually have an explicit selected-leaf, ancestor/common, or replicated-siblings scope. BMS export defaults to emitting the complete retained tree—every inactive branch and corresponding control statement—and never merely the selected materialized branch or its patches; flattening the active projection is explicit and lossy.
- Do not rely on current `libotoworm` evaluation for this contract: its loader discards inactive branches, and its fixed-roll, end-marker, mixed-nesting, caller-selection, and switch-fallthrough support is incomplete.
- Let versioned Lua chart modules generate SV, StepMania `SCROLLS`, and `SPEEDS` through deterministic generator entry points over normalized `p in [0,1]`. An entry point may return a function/closure recreated from persisted source plus explicit serializable captures/assets/hashes/API version/seed; mutable, ambient-state, opaque-VM, or call-order-dependent captures reject. Preview and export use the same bounded fixed/adaptive sampler.
- Include linear, endpoint-safe exponential, constant, finite two-region bump, multiplication, and typed Dirac-impulse primitives. A bump takes user-specified `Len(A)` and derives `Len(B) = TotalSegment - Len(A)`; balancing may solve `X` or `Y` so the normalized weighted area is 1.
- Run normalization and bump balancing as ordered post-processes over the raw typed batch; they can preserve prior integrated scroll displacement or absolute distance for generated or selected existing segments.
